4. ДОРАБОТКА СУЩЕСТВУЮЩЕГО TRAIN-001
- Использовать существующие Kotlin ReverseF, LearnedMemory, MemoryReplay, TrainModel, OfflineTrainer, TrainCheckpoint; сохранить идентичность исходной математики там, где корректна.
- Расширить CLI и конфигурацию с двух диагностических update до конечного бюджетного train/eval-loop, с контрольными точками, отказом при несоответствии experiment/data/schema и возможностью точного resume после аварии. Не стартовать длительное обучение автоматически.
- Встроить честный dataset/eval для задач 005B с обучаемым Wk/Wv и реальным причинным порядком. Не передавать gold/slot через внешние fabricated keys; внешние поля WRITE/QUERY допустимы только если явно часть входа и одинаково доступны baseline.
- Обучение на train, отбор по validation, locked test без адаптивной утечки; 1/2/3 записи, перезапись, порядок, длины до96, erased-control, memory ablations и baseline GRU; минимум одинаковые eval-datasets и отчёт о parameter/compute fairness.
- Устранить/задокументировать исследовательские ограничения сейчас: Double-only, episodes<=32, route fixed, no full S6, no AMP/FP16 equivalence. Если нужны изменения, добавлять отдельные подтверждаемые тестами контракты; не обходить silently собственные guards.
- Нормативные ограничения весов сохранить как baseline. Ослабленные ограничения допустимы только как отдельно маркированная контролируемая ablation, без скрытой подмены спецификации.
- Сохранить deterministic seed, source/weight/dataset SHA, metrics, checkpoint weights+optimizer+RNG+cursor+config. При сбое или corrupted files fail-closed либо явно обоснованный recovery; проверить точное resume на CPU.
- При необходимости GPU backend исследовать отдельно: Kotlin Double trainer не становится CUDA-ready от наличия RTX. Перенос на PyTorch разрешён только при сравнении forward/backward с Kotlin и документированных отклонениях; не создавать новый нейронный мозг.
