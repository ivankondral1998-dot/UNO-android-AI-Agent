# UNO F DIAG/FIX 005 — исследовательская диагностика

Причина провала 004 подтверждена при проверке исходников и градиентов: `UnoF.sequence()` вызывает `forward_event()` без `keys` и `values`, то есть путь семантической памяти пуст, `r=0`. Градиент `Wq` отсутствует, а `Wr` равен нулю. Раньше сеть пыталась выучить все задачи только за счёт рекуррентного состояния, при изменении общих весов разрушив старый навык.

## Быстрая проверка

1. Распаковать в `D:\OwnNeuralNet\UNO_F_DIAG_FIX_005`.
2. Запустить `TEST_DIAGNOSIS_005.cmd`.
3. Ожидается `DIAG_005_PASS=13`. Это CPU-проверка, не обучение и не изменение весов.

## Что реально исправлено в прототипе

Файл `uno_diag_fix_005.py` включает **отдельную адресную память**, написанную на основании наблюдаемых событий (не меток ответа), и отдельную обучаемую голову. Прежний F и его выходная голова заморожены. Записанные факты можно прочитать без изменения весов F. Детектор проверяет сохранение старых логитов без изменений. Это **исследовательский прототип**, не внедрение в UNO.

## Чего пока нет

Задачи с новым нейронным считывателем **не обучились устойчиво** на CPU в пробных 180–240 шагах, точность часто остаётся в районе случайной. Поэтому экспериментальное обучение через `uno_diag_fix_005.py` НЕ предлагается как готовое решение и не запускается по умолчанию. Программный идеальный декодер не эквивалентен обученной нейросети. Для реального исправления нужно спроектировать и проверить обучаемый адресный контроллер, сохранить контракты S4 и не изменять существующие производственные исходники без отдельного решения.

## Защита исходников

Этот пакет не меняет GitHub и не записывает ничего в папки старых экспериментов. Запуск `TEST_DIAGNOSIS_005.cmd` создаёт только временные тензоры в RAM. Настоящие веса 003 и 004 не включены в архив, т.к. находятся у владельца на Windows.
