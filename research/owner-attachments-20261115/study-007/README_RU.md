# UNO S4 Working Memory 007 — исследовательский прототип

**Цель:** отделить обработку событий рекуррентным F от адресной рабочей памяти. Проверить две/три ячейки, перезапись и чтение через исходную формулу ASTRA S4, не изменяя Kotlin и исходный F.

## Что реально происходит

- Для каждого входного события, включая шум, выполняется **исходный F S4/S5**; вычислительное состояние `s` обновляется. Оно не «замораживается» как в эксперименте 006.
- Во внешней адресной памяти контроллер сохраняет только наблюдаемые `WRITE(value,slot)`; новый `WRITE` того же адреса перезаписывает значение. Нейросеть не обучается самостоятельно определять, какие события записывать: маркер `WRITE` предоставлен данными.
- На последнем событии `QUERY(slot)` все 2 или 3 записи передаются в **исходный `UnoF.forward_event(keys=...,values=...)`**. Там выполняются нормативные `z0`, `q=tanh(Wq z0)`, softmax по всем кандидатам `q·key/sqrt(m)`, `r=sum(ω·value)`, `z=tanh(z0+Wr r)` и S5; K=2, маска полная.
- Идентификатор запрошенного адреса передаётся как цель `g` (one-hot) и остаётся также в поле события; это исходная информация запроса, не правильный ответ.
- **Обучаются только `Ug`, `Wq`, `Wr` и отдельная выходная головка**, с L1-проекциями по контрактам. Исходный F и его другие веса взяты из CPU-эксперимента 006 и заморожены. Работает дополнительный адресный loss по известному из запроса slot ID (по ответу используется обычный BCE).
- Ключи памяти фиксированы как ортогональные векторы ±0.99, значения передаются как фиксированные векторные кодировки наблюдённых чисел и лежат в [-1,1]. **Это не полноценная Astra memory:** нет обучаемых `Wk/Wv`, raw/provenance, согласий/TTL, exact retrieval, S6 или trainable WRITE gate.
- `no_memory` сравнение имеет тот же замороженный F, но без чтения, и тренирует только новую головку; число обучаемых параметров различается (129 против 49 281), так что это диагностическая абляция, а не честный рейтинг двух одинаковых по мощности моделей.

## Windows, RTX 4060 Ti

1. Распаковать архив целиком в `D:\OwnNeuralNet\UNO_S4_WM_007`.
2. Закрыть или завершить другие обучающие Python/CUDA-процессы.
3. Дважды нажать `START_GPU_007.cmd`. Скрипт проверит исходники и проведёт 6 коротких запусков: для 3 задач отдельно без памяти и с S4 (по 200 шагов).
4. Результаты появятся в `D:\OwnNeuralNet\uno_s4_wm_007_gpu\metrics.json` и отдельных файлах `.pt`.
5. Если выполнение остановилось, **не удалять папку вывода**. Использовать `RESUME_GPU_007.cmd`: он возобновит незавершённую пару с последнего checkpoint. `START` отказывается перезаписывать существующий вывод.

Температура и занятая VRAM проверяются через `nvidia-smi` при старте и каждые 25 шагов; пороги 80 °C и 7000 MiB. Мониторинг fail-closed при ошибке `nvidia-smi`. **Это не аппаратная гарантия**, а периодический контроль. На CPU измерения CUDA не производились; реальная работа версии 007 на твоей RTX пока не проверена.

Ограничение времени `--max-seconds 600` действует для **каждой обучающей пары**, при прерывании сохраняется атомарная контрольная точка. Итоговая оценка может занять больше времени и при её прерывании повторяется при восстановлении. Общее количество шагов в стандартном запуске — не больше **1200**, плюс оценка.
