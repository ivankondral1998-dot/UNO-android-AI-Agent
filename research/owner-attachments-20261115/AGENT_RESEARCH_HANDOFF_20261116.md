## Проверка без проблем с инструментами

Файлы ChatGPT уже смонтированы в `/mnt/data` в текущей рабочей среде. Для локальных файлов использовать обычный Python, **не повторять ненужную materialize-операцию**. Для GitHub читать актуальный `main` отдельно, research отдельно. Подключённый GitHub API принимает текст/base64, но не `/mnt/data/...` как путь к бинарному вложению; это ограничение передачи, а не ошибка содержимого ZIP.

Запуск существующего строгого проверяющего скрипта (из checkout):
```sh
python3 research/owner-attachments-20261115/verify_archives.py --source /mnt/data --repo /path/to/research-checkout --require-all-git
```
Новый дополнительный скрипт (read-only, JSON stdout, статус 0=нет ошибок, 1=ошибка проверки, 2=неполный Git-архив при `--require-all-git`):
```sh
python3 research/owner-attachments-20261115/audit_research_artifacts.py \
  --source /mnt/data \
  --manifest research/owner-attachments-20261115/ARTIFACTS.tsv \
  --extras research/owner-attachments-20261115/EXTRA_VERSIONS.tsv \
  --repo /path/to/research-checkout --require-all-git
```
При отсутствии checkout `--repo` опустить: Git-статус будет `DECLARED_UNCHECKED`, а не `PASS`. Для ранних версий, загруженных под тем же именем, исходные байты необходимо брать по точному ID вложения из `EXTRA_VERSIONS.tsv`; скрипт их не подменяет поздними файлами. Скрипт не связывается с GitHub и не запускает обучение.
