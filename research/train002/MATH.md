# TRAIN-002 — exact scope of the chronological candidate

Baseline: TRAIN001 b371b627ef743b876e13daadf3b57d6013f37652, Astra01 S4/S5, Astra02 Ω, Astra03 L4, Astra04 write equations, Terra/Grok pins in TRAIN001 evidence/continuation/source-pins.json. Those originals and TRAIN001 files are unchanged. This is a research candidate, not a revision to their production authority.

Original address: k_i=tanh(Wk h_i). Candidate: k_i=tanh(Wk h_i+0.5 c_i). Value stays v_i=tanh(Wv h_i); f_e=0 in this synthetic protocol. c_i repeats [u,u²,t,t²,v,v²,1,-1] sixteen times, with u=write ordinal/4, t=source event sequence/96, v=observed-slot version/4. All are immutable at write and independently known from the causal raw event prefix. More than4 writes or96 events is refused; no silent clipping/truncation. Fields are not computed from gold record, answer, future count, or model predictions.

The candidate deliberately changes Astra04's key preactivation by a fixed public feature. It retains the same free Θ/schema/dimensions, all row caps and S4 softmax law. It is not claimed algebraically identical to the original address equation. |c|∞≤1, |h|∞≤1, ||Wk||∞≤2 give |preactivation|∞≤2.5 (plus the declared FP32 cap tolerance); keys remain in [-1,1]. For δ_i=bar(k_i)⊙(1-k_i²), ∇Wk+=δ_i h_iᵀ and bar(h_i)+=Wkᵀδ_i as before. No score/gradient for c is missing: c is independent of Θ on a fixed observed trajectory. Source F and earlier memory reads stay on the shared graph. S5 formulas/order, K2, alpha=rho=.5 stay unchanged. This does not establish global event contraction or full S6/AMP/FP16 equivalence.

Chronology maintains strictly increasing event IDs, record ordinals, previous/next event links and observed-slot previous-version chains; all versions remain present. `neighbor()` is a structural API tested separately. Neural replay never calls it to choose an answer. Every past record remains a softmax candidate. Query anchor/opcode is a public request supplied equally to every model. There is no gold-based bank filter, fixed answer key or raw-value read shortcut.

Two independent experimental axes: original/coded chronology, legacy/typed payload supervision. Legacy supervises one coordinate of one queried record; it asks for a raw scalar for r1–r4 and a slot code for r5. With the same writes and different future queries, one v0 can be assigned two incompatible targets. Example targets .25 and -1 imply mean weighted value term≥.2*(1.25²)/4=.078125. This local contradiction is proven; it is not proof that the full F cannot encode both facts or that it alone causes all r5 errors.

Typed payload supervises [raw scalar, public slot] for every write, independent of future request. It changes both fields and coverage; typed-versus-legacy measures that combined intervention. Clock comparisons hold the entire payload/mask protocol fixed. No claim of improved chronology is justified merely by a better typed payload result.

Frozen Wk/Wv remain bitwise unchanged, but source F can still learn through the frozen matrices. Random keys depend deterministically on the raw past prefix, independent of Θ/gold; they are not a global event-ID code that can be memorized across episodes. Value permutation reverses key↔value association within the already eligible bank. Reverse-pairs preserves association and immutable header IDs, testing list-storage permutation invariance. Clock shuffle exchanges clock codes only among already present entries. These inference interventions are distinct from training those control arms from scratch.

Precision: FP32 weights/gradients/Adam, FP64 threshold for Euclidean L1 projection then cast, decoded cap tolerance2e-6, no TF32/AMP. The original Double forward/gradient matches are checked when clock gain0; finite differences and FP32-vs-Double checks cover the new candidate. No Android/device/quality theorem follows.
