**Состав.** 01_MATH_CANDIDATE_RU.md — исправленный единый математический кандидат с доказательствами и результатами экспериментов. 02_ERRATA_RU.md — 16 адресных записей, включая старые правки, ограничения и новые контрпримеры. 03_GATES.tsv — 105 индивидуальных строк D/X/B/M/O/T с исходной формулировкой, статусом настоящего аудита и остаточной проверкой. SOURCES.tsv связывает каждый файл входного ZIP с относительным путём, SHA-256, размером и происхождением. Дубликаты с одним SHA не являются независимой репликацией. В tests — восемь исполняемых малых проверок, в evidence — реальные результаты. Запись для существующего журнала находится в 04_JOURNAL_ENTRY_RU.md.

**Воспроизведение.** Распаковать исходный ZIP и этот ZIP в разные каталоги. Из каталога результата выполнить:

```sh
sh tests/run.sh /путь/к/распакованному/входному/ZIP
```

Использованы Python 3.12.14, NumPy 2.3.5, FP64 для численного оракула и один поток BLAS. Функция потерь вычисляется при замороженных исходных точках; конечные разности обратимо возмущают отдельную координату только в оперативной памяти. Тесты не выполняют шаг оптимизатора. Восемь скриптов завершились с кодом 0, перечень — evidence/RUN_ALL.log. Они проверяют арифметику и контрпримеры; «exit 0» включает успешное обнаружение ошибки. Это не число закрытых интеграционных gates.

**Открытые вопросы по приоритету**

1. **SPECIFIED_UNTESTED.** Какой принятый law и replay ABI применяются в реальном S6? Эталон для следующего сопоставления — три случая из §§4–5: K=2 из состояния, крайние logits и точная граница бюджета. Нужны instrumented A/C/B и trace по шагам на целевом backend.
2. **SPECIFIED_UNTESTED.** Нет сквозного прогона одной сессии GOAL → S4/S6/S5 → PROPOSAL → trusted dispatch/readback с гонками STOP/revoke и аварийным восстановлением. Текущие математические свидетели не аттестуют T01–T17 end-to-end. Входная запись «456/456» относится к прежнему host-прогону. Kotlin-компилятор в этой среде не обнаружен; нового JVM-прогона здесь нет.
3. **REQUIRES_DATA.** Нет независимых per-episode предсказаний итоговых обученных checkpoint для повторной оценки всех заявленных GPU/CPU метрик. 006 представлена не полностью. Для отделения механизмов нужны согласованные абляции, независимые seed/семейства и оценки условных трудных эпизодов. Механистические градиенты TRAIN001 на приложенных fixtures воспроизводимы уже сейчас.
4. **REQUIRES_DATA.** Нужны разрешённые данные по E01–E11, frozen tokenizer/DSP, decoded веса выбранного ABI, независимые метки и holdout. Peak PSS, latency, joules/task, акустический wake и независимые физические эффекты на A52 не установлены. Строгий offline включает локальность фактического provider.
5. **OWNER_DECISION.** O01–O08 остаются индивидуальными. Разрешение разрабатывать проект и решение принять математическую гипотезу — отдельные решения.
