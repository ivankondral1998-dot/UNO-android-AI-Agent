# UNO B2-512 R5.4 — проверка полного контекста

**Длительное обучение заблокировано.** Исследовательский тренер исправляет обрезание диалогов и проверяет прохождение сигнала от вопроса к ответу. Контрольная точка шага 50 прошла проверки геометрии и ограничений весов. В коротком опыте UNO всё ещё не выучила соответствие между двумя вопросами и их ответами.

Репозиторий `ivankondral1998-dot/UNO-android-AI-Agent`, ветка `research/uno-train-001-s4-20261115`. Исходный HEAD `4d80ba31e65bab660e23e353dfae7f16535bc63b`. Все 102 файла пакета передачи сверены по размеру, SHA-256 и Git blob SHA в этом HEAD. Веса взяты из исходного CUDA Bridge. SHA-256 родителя `33186b7515eef3a7d3954d94d9c31cd1969cdb1ce2f811c80e020cfd12f58a62`. Оператор R5.4 сохраняет фиксированный K=1, 512 координат состояния и общую матрицу входных и выходных токенов.

## Что изменилось

| Дефект или ограничение | Статус |
| --- | --- |
| FAST03 заводит окно внутрь вопроса или ответа, сбрасывая состояние | Диалог идёт с BOS до последнего ответа. Слишком длинная запись целиком исключается и учитывается по источнику. Максимум по умолчанию 512 входных токенов. |
| Реплики пользователя могут потерять связь с разметкой ответа после обрезания | Пользовательские реплики и маркеры ролей находятся во входной последовательности. Ошибка считается только на токенах ассистента, включая его EOS. Паддинг не участвует. Диалоги не склеиваются. |
| Координата позиции `t/L` зависела от фактической длины окна при смене формата обработки | Координата стала причинной по явному правилу `min(t/128, 1)`. Потоковая генерация сохраняет состояние и позицию. Это новая исследовательская конфигурация входа и новая линия чекпойнтов. |
| Измерение ошибки ответа могло расти в качестве без улучшения связи с вопросом | Валидация сравнивает один ответ под двумя разными вопросами одинаковой токенной длины в обе стороны. Дополнительно проверяется генерация с нуля, включая настоящий EOS. |
| Подмешивание огромного числа языковых строк | Проба чередует два обновления на диалогах с одним на языке. Это фиксированная пробная пропорция по обновлениям. Счётчик целевых токенов выводится отдельно. Подбор смеси внутри языковых источников ещё нужен. |
| При отказе последнего сохранения терялась надёжная точка продолжения | Состояние сохраняется после каждого завершённого обновления. Чекпойнт публикуется через временный файл с fsync и атомарной заменой. Две последние корректные версии, контрольная сумма, блокировка одного писателя, восстановление из предыдущей при повреждении контейнера. |
| Механический CUDA-пробник мог открыть длительный запуск | Новый `train` отказывает до выделения устройства. `probe` ограничен 12 шагами и 240 секундами плюс до 10 секунд на остановку. Стандартный Windows-запуск использует три шага и 150 секунд. |

Формат последовательности и старые идентификаторы сохранены. Состояние переносится внутри всей диалоговой последовательности. В языковом режиме обучаются отдельные окна одного документа с явным сбросом. Проба использует FP32, Adam с фиксированным LR, ограничение глобальной нормы градиента на 1 и прежнюю проекцию весов на ограничения R5.4. BF16 и fused Adam оставлены в историческом FAST03 эксперименте. Новый тренер их не допускает до корректных сравнений на целевом устройстве.

## Воспроизведение на Windows

Распаковать ZIP на диск D. В архиве каталог `trainer/r54_full_context` расположен рядом с существующими модулями FAST03. Сохранить это расположение. Нужны установленный `D:\UNO\env\Scripts\python.exe` с CUDA PyTorch, исходный `D:\UNO\B2_512\latest.uno` и готовый `D:\UNO\corpus_prepared_v4`. ZIP содержит исходники и проверки. Исходный чекпойнт остаётся в CUDA Bridge и на компьютере владельца.

Из каталога распакованного пакета в PowerShell запустить:

```powershell
& .\trainer\r54_full_context\PROBE_WINDOWS.ps1 -Out 'D:\UNO\r54_probe_01'
```

Для точного продолжения той же короткой проверки:

```powershell
& .\trainer\r54_full_context\PROBE_WINDOWS.ps1 -Out 'D:\UNO\r54_probe_01' -Resume
```

Для независимой сверки нормализованных ключей между выборками, без CUDA:

```powershell
& 'D:\UNO\env\Scripts\python.exe' -B .\trainer\r54_full_context\audit_split.py 'D:\UNO\corpus_prepared_v4'
```

Обёртка проверяет пути и направляет временные файлы и кэши на D. Внешний наблюдатель опрашивает одну физическую видеокарту, сверяет UUID и время снятия показаний. Остановка при 78 °C, 6500 МиБ, отсутствии датчика, просроченной телеметрии или зависании. Измерения дискретны. При аварийном прерывании доступен последний атомарно опубликованный шаг. При Ctrl+C текущий завершившийся шаг получает короткое время на сохранение. Идентификаторы вида `preflight-*.json` и `supervisor-*.json` связывают результаты пробы и пики телеметрии. Успешная механическая CUDA-проба сама по себе не даёт допуск к часам обучения.

## Чекпойнт

Контейнер `UNO-B2-CUDA-RESEARCH/V1`. Первая строка содержит идентификатор формата, вторая — SHA-256 содержимого. Далее сериализация PyTorch с безопасным чтением `weights_only=True`. Поля содержат 118 канонических тензоров FP32, состояния Adam для компактных обучаемых тензоров, шаг, состояния Python и Torch RNG, состояние CUDA RNG на CUDA и конфигурацию с привязкой к хешам кода, корпуса, словаря, родителя и устройства. Старый B2 шага 50 используется как веса при создании новой фазы, с новым Adam. Его старое состояние оптимизатора не переносится автоматически. Проверенный на сервере точный resume относится к одному CPU окружению. Формат является исследовательским контейнером PyTorch. Выпущенного импорта этих весов в Android пока нет.

## Данные, метрики и допуск

Вход проверяется по SHA-256 из FIX04. Принимается отчёт схемы `UNO-CORPUS-PREP/4` с нулём заявленных точных пересечений и без отсутствующих источников. `audit_split.py` независимо сверяет нормализованные точные ключи языка, диалогов и намерений. Смысловые дубликаты и качество очистки персональных данных требуют отдельного аудита. Статус корпуса остаётся исследовательским. В симуляторе никаких Android-действий не выполняется.

Долю полных диалогов проверять по источникам. Для продления работ нужно обосновать покрытие каждого важного источника. Пример с пропущенным контекстом исключается целиком. Диагностика сравнения вопросов использует минимум 20 пар на validation, требуя ≥75% корректных направлений, среднее преимущество ≥0,10 NLL на первом токене и корректное начало хотя бы в 50% из 16 свободно сгенерированных ответов. Эти пороги являются исследовательским фильтром для постановки эксперимента. Отчёт отдельно показывает точную генерацию вместе с EOS, падение языка и охват. Закрытая test-выборка сверяется по хешу, её содержимое в подборе и оценке чекпойнтов не участвует.

`study_context.py` проверяет намеренную подгонку, ответ на разные вопросы, новые формулировки, длинный контекст и затухание градиента. Сравнение идёт с необученным F, прежней точкой, биграммой и GRU-контролем. `study_behaviors.py` проверяет свободную генерацию по 4 синтетическим случаям в каждой из 8 категорий, включая смену темы, отрицания, конфликт и отказ. Для кандидата выводит деградацию относительно предыдущей точки. Эти малые тесты служат дымовой проверкой. При 0 исходных правильных ответов сохранение приобретённой способности оценить нельзя. Для приёмки нужны независимые размеченные случаи по каждому направлению, реальное качество, подтверждение на отложенной выборке и проверка забывания после следующего этапа.
