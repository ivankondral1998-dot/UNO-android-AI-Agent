## 1. Оптимизация вычислений
Исходный последовательный алгоритм L1-проекции сохранён. Для отсортированных gap g_i и cap C,
delta = min_k ((C + sum_{i<=k} g_i)/k); проекция sign(x)*max(delta-(max(abs(x))-abs(x)),0).
Эквивалентность следует из условия sum(max(delta-g_i,0))=C.
Операции выполняются в FP64, проверяется decoded_row_guard после преобразования; при непрохождении используется старый алгоритм.
200 сочетаний dtype/ширины/cap/масштаба, 6400 строк, max abs discrepancy 1.1920928955078125e-7.
Независимый KKT тест на 288 построенных строках, неизменность допустимых строк, отказ NaN/Inf/некорректных caps: PASS.
На 16 окнах реальной прозы, одинаковые начальные веса/данные/старый LR:
original CPU 16.5394 s, wall 8.5111 s;
projection_only CPU 11.7588 s, wall 5.9046 s;
flat_linear CPU 12.0578 s, wall 6.0730 s.
Во всех трёх случаях train losses совпали, validation256 NLL 6.242189258337021.
Flat linear не принят. Рекуррентный event/forward сохранён побайтно; исходный backend и зависимости сохранены.
Это один малый сравнительный эксперимент, не гарантия ускорения на Acer.

## 2. Эффективность обучения

validation: 16 равномерно выбранных независимых фрагментов по 64 цели, 1024 цели; тестовый split не используется для оценки.
Seed 11: PPL 513.684 -> 235.993, CPU 49.281 -> 49.210 s.
Seed 37: PPL 513.744 -> 238.234, CPU 49.896 -> 50.507 s.
Выбор warmup16 для ограниченного пилота; исходный режим доступен --warmup 1000.

Новая модель пока хуже даже unigram. Результат подтверждает выигрыш начальной стадии, не итоговую языковую компетентность.
До шага 64 сравниваемая траектория совпадает с новым CLI; её долгосрочная пригодность не проверена.
Никаких весов из диагностики не публикуется. Основное обучение не запускалось.
