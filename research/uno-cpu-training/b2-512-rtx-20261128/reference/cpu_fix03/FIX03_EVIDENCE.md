## Оптимизация вычислений
Новый analytic_backward.py реализует обратный проход в пределах фиксированного TBPTT окна.
Для g=adj(h_next) delta_v=.25*g_j*(1-v^2), delta_u=B^T delta_v*(1-u^2).
adj(h0)=.5*g+sum(A^T delta_u), adj(z)=.5*adj(h0)+sum(C^T delta_u).
Далее производная двух tanh, carry=.5*adj(h0)+Us^T delta_pre.
Градиенты A/C/B суммируются матричными произведениями по времени;
E получает одновременно градиенты выходной головы и lookup с index_add по повторным токенам.
Градиент на входном состоянии проверен, но не передаётся сквозь границу окна, как в исходном TBPTT.
Восемь сочетаний FP32/FP64, d64/128/512, длины 1/7/16, все веса и состояние:
макс. абсолютная разница FP32 2.9802322387695312e-08, FP64 4.163336342344337e-17.
Все проверенные значения loss и state совпали в допусках.
Исходный autograd сохранён через --backend autograd, по умолчанию analytic.
Проекция: быстрый выход для уже допустимых строк; удалены повторные полные сканирования,
но конечность каждого входа и decoded cap каждого изменённого блока проверяются.
Проверка model.validate() при загрузке/экспорте сохранена.
200 сочетаний/6400 строк из FIX02 и независимые KKT контрпримеры повторно проверены.
Отдельные диагностические сравнения аналитического backward и сокращённых сканирований сохранены в логах.

## Проверенные, но не принятые улучшения качества
1. Инициализация b_text логарифмом частот train-токенов (см. A Natural Bias for Language Generation Models).
Два seed, 64 окна/1024 цели. PPL около 184.04/184.05 против 235.99/238.23 у нулевого bias,
но initial NLL уже 5.2157, финальное улучшение всего ~.00055 NLL. При удалении контекста
между окнами разница ~.00001, поэтому снижение PPL не доказывает лучшую обученность контексту.
Частотный prior использует полный train, не validation/test; подсчёт частот не включён в CPU-замеры update.
Не принят как default.
2. Увеличение E вдвое с повторной проекцией: на двух seed PPL 244.176->241.059 и 243.488->242.730.
CPU соответственно 42.631->45.208 и 46.883->42.665 s. Выигрыш мал, устойчивое преимущество
по затратам/качеству не установлено. Не принят. Warmup16 из FIX02 сохранён.
Новая более высокая языковая компетентность не доказана. Все проверки качества — малые диагностики,
не итоговый закрытый тест и не полное обучение. Не сохранялись диагностические веса вне временных каталогов.

## Исправления безопасности и состояния
- Контроллер теперь отправляет timestamped monotonic heartbeat неблокирующей записью.
Старые/будущие heartbeat не возобновляют lease. Переполненный pipe останавливает работу.
Запросы телеметрии ограничены 2.5 s; верхняя граница lease 5 s. Внешний дедлайн train/resume — seconds+60.
- Windows Job Object: добавлен лимит committed memory 4096 MiB для рабочего дерева и проверка настроек
через QueryInformationJobObject, существующий kill-on-close сохранён. Linux не доказывает работу Windows API.
- CSV LHM: строго один живой экземпляр, время запуска процесса, время файла и строки, идентификатор CPU.
Пределы 85°C, 95% system CPU, RSS 4096 MiB, свободная RAM 1536 MiB, диск 512 MiB не ослаблены.
Убран повторяющийся блокирующий запрос датчика на каждом шаге; отдельный контроллер и проверка перед сохранением сохранены.
Фактическая задержка защиты зависит от планировщика и драйвера; аппаратным мгновенным предохранителем не является.
- Checkpoint: потоковая SHA-проверка, предыдущая версия через hardlink с fallback на проверенную копию.
Устойчивость к kill непосредственно перед atomic replace проверена. При поддержке hardlink нет повторной записи старых 60 MB.
NTFS, питание и аппаратная долговечность не проверены.
- До загрузки PyTorch проверяются dtype, shape, raw finite, точный инвентарь, Adam state и hyperparameters,
целый step, learning rate, RNG и cursor. Восемь файлов с валидным SHA и ошибочной схемой отвергнуты.
- CHECK дополнительно проверяет все 512 байтовых/составных токенов, топологию BPE и повторное
кодирование 23 фрагментов всех произведений (21101 токен). Корпус неизменён, 32/32 манифест.
- TEST использует проверку полного checkpoint, а не только model.state_dict.
