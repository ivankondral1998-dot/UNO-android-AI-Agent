# UNO — Unified Neural Organism

> UNO — Unified Neural Organism. A commercial, fully offline Android AI agent built around a unified adaptive neural architecture, new trainable weights, plastic connections, and verified experience-based learning.

**UNO** — самостоятельный коммерческий ИИ-агент для Android. Его цель — единая нейроноподобная вычислительная организация, охватывающая не только модель и веса, но и восприятие, общую память, связи, выбор действий, проверку последствий, обучение и управление ресурсами.

**Статус: ранняя стадия разработки.** Этот репозиторий создан как новая независимая основа продукта. Наличие документации не означает, что UNO Core, автономное обучение, полноценное Android-приложение или коммерческий APK уже реализованы.

## Основной архитектурный принцип

**Один адаптивный организм, а не ансамбль отдельных «мозгов».**

UNO исследует возможность описать работу программного агента общей математической организацией:

- **Восприятие:** локальный звук, текст, сенсоры и текущее состояние устройства.
- **Новые обучаемые веса:** собственная модель и представления, не зависимые от старых весов Jarvis.
- **Нейроноподобные связи и память:** единое изменяемое состояние, ассоциации, пластичность и сохранение опыта.
- **Адаптивные вычисления:** включение нужных вычислительных путей и повторные проходы общего оператора с учётом бюджета.
- **Цели и действия:** формирование гипотез, планирование и вызов разрешённых функций Android.
- **Проверяемые последствия:** независимый native readback вместо доверия к текстовому «успешно».
- **Развитие:** контролируемые исследования новых навыков, расширения структуры и защиты от забывания.

Это функции единой системы, а **не предписание создать отдельный сервис, мост или автономного агента для каждого пункта**. Системные Android API неизбежны для доступа к оборудованию и разрешённым действиям; они не являются вторым интеллектом.

## Исследовательская формула UNO

Исходная концепция UNO используется как **отправная математическая гипотеза для всей системы**, а не только для инференса весов.

Выбор вычислений с учётом наблюдения, общего состояния и бюджета:

```text
I_t = π_B(x_t, S_t)
```

Повторное уточнение состояния **одним разделяемым обучаемым оператором**:

```text
h_t^(k+1) = h_t^k + M_(t,k) ⊙ R_(φ,G)(h_t^k, z_t)
```

Предложение действия и изменение состояния:

```text
(â_t, S_(t+1)) = D_G(h_t^K, z_t, S_t)
```

Внешняя по отношению к модели граница полномочий:

```text
a_t = Authorize(â_t, Owner, Android)
```

Предполагаемый цикл:

```text
Наблюдение
   ↓
UNO: активные связи + общие веса + циклы + состояние
   ↓
Предложение решения
   ↓
Android: разрешения + подтверждение + STOP
   ↓
Разрешённое действие
   ↓
Независимая проверка фактического результата
   ↓
Обновление опыта и пластичных связей UNO
   ↺
```

Маски должны **реально пропускать вычисления**, чтобы экономить ресурсы, а не обнулять результаты после уже выполненных дорогих операций. Сама формула, её оптимальность и универсальность не доказаны. Операторы, данные и новые веса предстоит разработать, обучить и проверить.

**Целевая метрика:** энергия на независимо подтверждённую успешную задачу при сохранении приемлемого качества, безопасности и задержек. Оценки FLOPs или времени на ПК не подменяют измерения батареи Android.

## Обучение и эволюция

Изучаются пластичная память, обучение по подтверждённым последствиям, управляемое увеличение ёмкости, сохранение старых навыков и восстановление после сбоев. Исследовательская линия NCR-EVO может применяться для изолированного поиска вычислительных структур, **но не является готовой самоэволюцией продукта**.

Новая модель должна сравниться с простыми базовыми решениями, включая таблицу ассоциаций и фиксированную сеть. Рост количества параметров, изменение файла весов и высокий процент на игрушечном наборе **не доказывают улучшение интеллекта**.

## Android и безопасность

UNO — прежде всего **Android-продукт**, поэтому инженерные критерии включают реальный UX, запуск без интернета, расход RAM/CPU/батареи, устойчивость фоновой работы, совместимость с Android и воспроизводимые APK/AAB.

Нейронная система не вправе самостоятельно расширять системные полномочия. Разрешение на действия определяется пользовательским согласием, Android permissions, актуальным состоянием задачи, STOP/отменой, подтверждениями и независимой проверкой результата.

Нейронный прогноз ≠ разрешение. История ≠ текущее состояние устройства. Отправленная команда ≠ выполненная команда.

## Отношение к прежнему Jarvis

JarvisLab — **отдельный старый проект**. Из его наработок разрешено выборочно переиспользовать только необходимые и проверенные локальные решения: аудио, голосовой жизненный цикл, Android execution, STOP, authority, подтверждения и readback — **после проверки исходников, происхождения, лицензий и пригодности**.

Нельзя автоматически переносить старые веса v0/v1/v2, прежнюю многослойную агентную архитектуру, облачные зависимости или полное дерево Android-приложения. Старые исследовательские результаты могут использоваться как сравнительные ориентиры, но не выдаются за реализованные функции UNO.

## План разработки и критерии готовности

| Этап | Ожидаемый результат | Состояние |
| --- | --- | --- |
| 0. Независимая основа | Приватный репозиторий, требования, правила, резервирование | В работе |
| 1. UNO Core | Новые обученные веса и воспроизводимый нейронный runtime | Не реализовано |
| 2. Пластичность | Полезное обучение на проверенных последствиях | Не реализовано |
| 3. Android | Локальный слух, голос, разрешённые действия, STOP | Не интегрировано |
| 4. Единый цикл | Восприятие → UNO → действие → readback → опыт | Не реализовано |
| 5. Проверка | Регрессия навыков, ресурсы, автономность, безопасность на устройстве | Не проведена |
| 6. Коммерческий выпуск | UX, политика конфиденциальности, лицензии, подписанный AAB/APK | Не начат |

Не называем систему готовой только потому, что собран APK, прошли JVM-тесты или появилась документация. Отдельно учитываются source / host-tested / built / device-verified / release-ready.
