## Что теперь есть
Главный экран: офлайн-чат; «ПРОВЕРИТЬ UNO · ОДИН ТЕСТ»; копирование полного JSON; видимый STOP; сворачиваемый инженерный раздел. Все прежние ручные проверки (SQLite, owner NOOP, точная память/отзыв, маркер, stress, оформление) сохранены в раскрываемой лаборатории.

Один запуск `UNO_ONE_TAP_DIAGNOSTIC/1`: ограниченный `DeviceLab.QUICK` (CPU/RAM, integrity, queue STOP, app-private IO и сенсоры), пассивная проверка существующего SQLite, независимое открытие существующей шифрованной памяти и её source SHA, повторное чтение существующего локального маркера. JSON сохраняется в `files/diagnostics/probe_latest.json` через существующий `DeviceProbe.persist` и перезаписывает только этот текущий диагностический файл. QUICK использует один повторно используемый IO-fixture; отдельные записи exact-memory и новые маркеры не создаются. Никакие старые данные не удаляются.

`PARTIAL` — нормальный итог при отсутствии FAIL: самотест не может автоматически получить согласие, доказать эффект Android или качество нейросети. Отсутствие прежней записи = `NOT_RUN`; неизвестная/истёкшая = `UNKNOWN`, отзыв доступа = `DENIED`; ошибки = `FAIL`; прерванные тесты = `ABORTED`. Детали и причины — в каждом вложенном шаге. STOP не откатывает уже начатые эффекты, а запуск лаборатории не использует сетевые разрешения.

## Доставка без засорения телефона APK

Текущий CI workflow собирает **отдельный** пакет `org.unovyra.uno.scaffold.ci<RUN_ID>` для изолированной проверки, а не APK для обновления существующей установки. Признак in-place update отсутствует: applicationId другой, совместимость ключей подписи не установлена. **Владельцу не предлагается установка нового CI APK.** Для будущих обновлений одного установленного UNO нужны стабильный applicationId и постоянный доверенный signing key, проверенные до установки. Не менять package ID существующих данных вслепую и не удалять прежние APK без согласия владельца.
