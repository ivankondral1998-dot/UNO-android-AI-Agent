# UNO — самостоятельное доверие «профессору» и «ученику» (07.11.2026)

**Результат: частичный успех только на простом компьютерном симуляторе.** Система получила **только наблюдения и проверенные симулятором последствия выбранных действий**, без готовой метки «старое правило A / новое правило B». Показала автоматическую смену доверия. Но на новом правиле уступает варианту с постоянно включённым «учеником», а на принципиально новой комбинации признаков — простой таблице. **Не выбирать эту архитектуру как ядро UNO.**

## Что именно сделали

Взяли **реальные ранее обученные** маленькие веса «профессора» (169 параметров, неизменный оригинал `provenance/SOURCE_SLOW_PRETRAINED.pt`, SHA-256 `2ab3c1472c32fb1739c9432a4b603a579cc8e36ac41188e0576a422f73a147fe`). Его задача — предсказывать полезность двух действий для старого закона A. Это **не общая интеллектуальная модель**.

Добавили **156 обучаемых числовых параметров «ученика»**. Один общий оператор формирует решение `z = z_профессора + g × поправка_ученика`. Доверие `g` пересчитывается по разнице ошибок вероятностных прогнозов двух частей **после задержанного, подтверждённого результата выполненного действия**. Никакого указания на текущий закон A/B механизм не получает. Веса профессора остаются замороженными.

**Важное уточнение:** `g` — вручную заданный математический механизм оценки качества прогнозов, **не** отдельная обученная нейросеть-распознаватель ситуаций. Результат подтверждает, что такой механизм *частично* различает условия по последствиям, но ещё не доказывает автономную способность UNO понимать контекст.

## Методика, закреплённая до испытания

- 36 новых задач, по 12 случайных вариантов **похожего**, **противоположного** и **нового** законов; семена `PROTOCOL_LOCK.json`.
- В каждой задаче 80 решений по A → **160 по B** → 80 по A. На входе у всех законов одинаково распределённые четыре числовых признака: **по одному наблюдению нельзя узнать текущий закон**. Переход A→B алгоритмам не сообщается.
- 25% случайных исследовательских действий; итог действий — вероятностный (0/1), с задержкой в три шага. Модель видит **только исход выбранного действия**, а не результат альтернативы, скрытый закон или правильную метку ответа. Истину использует лишь отдельный оценщик.
- Пять вариантов: профессор без обучения; ученик постоянно активен; **автоматическое доверие**; простая таблица с забыванием и тем же профессором как начальной подсказкой; **диагностический оракул, которому специально открыта истинная метка** (нечестная верхняя граница, не участник выбора победителя).
- Объединённый вариант и «ученик всегда включён» имеют одинаковые **325 коэффициентов** (169 старых замороженных + 156 новых обучаемых), одинаковую скорость обучения и начальные обучаемые веса, **но выбранные ими действия и полученные награды могут различаться**. Вычислительное время и энергия не уравнены. Таблица имеет другую ёмкость.
- Проверяем отдельно точность онлайн-решений, ожидаемые потери, работу в B, возвращение к A, удержание на новых наблюдениях и перенос на сдвинутые входы.

`PROTOCOL_LOCK.json` SHA-256: `5645d315b2b9d7ba324955f2d6f01f1e99e5f65493fb85924d396379e96797b7` — локальный замок, **не внешнее доказательство времени его создания**.

## Результаты (онлайн, с 25% исследовательских действий)

Средняя доля выборов правильного действия по 12 сценариям каждого закона:

| Закон B | Способ | Точность B | После возврата A |
|---|---|---:|---:|
| Похожий | профессор | 70,5% | 82,7% |
| | ученик всегда | 71,0% | 79,3% |
| | **автоматическое доверие** | **71,9%** | **82,5%** |
| Противоположный | профессор | 26,2% | **83,7%** |
| | ученик всегда | **55,5%** | 70,9% |
| | **автоматическое доверие** | 49,8% | **79,8%** |
| | простая таблица | 38,9% | 62,7% |
| | оракул с истинным контекстом | 56,0% | **83,7%** |
| Новый | профессор | 51,9% | 84,1% |
| | ученик всегда | 51,6% | 74,7% |
| | **автоматическое доверие** | 51,5% | 83,4% |
| | **простая таблица** | **56,3%** | 71,6% |

На противоположных законах средняя степень доверия ученику: **0,007 на первом A → 0,622 на B → 0,071 после возвращения A**. То есть переключение происходит **по задержанным последствиям**, а не благодаря готовой метке. На последних 80 шагах B точность автоматического варианта выросла до **60,4%**; это динамика внутри испытания, а не отдельный закрытый набор.

**Парные интервалы** (bootstrap по 12 сценариям, 95%): на противоположном B автоматический метод относительно замороженного профессора **+23,6 п.п.** `[+20,3; +27,2]`; относительно постоянно активного ученика **−5,7 п.п.** `[−7,6; −3,7]`. На возврате A он выше ученика на **+8,9 п.п.** `[+5,9; +12,2]`, но хуже профессора на **−3,9 п.п.** `[-5,5; -2,3]`. Поэтому преимущества есть, но **лучшего метода для всех режимов нет**.

На новом B автоматический вариант **не превосходит профессора и проигрывает таблице**; обобщение на новые виды задач не получено.

## Где эксперимент ещё слаб

1. Это **вероятностный математический симулятор**, два действия и четыре числовых входа. Нет естественного языка, сенсоров, долгосрочной памяти организма, реальной причинности или Android.
2. Нельзя предугадать смену закона без информации, отличающей его от старого. До задержанного последствия система не имеет оснований определить, что B уже начался. Даже при правильном обучении на каждом переходе неизбежен период ошибок.
3. Доверие основывается на сконструированной формуле относительной ошибки, а не на самостоятельно найденных понятиях. Оно может ошибаться при шуме, неправильных исходах и в недоступных видах задач.
4. «Verified» означает только, что результат вернул независимый от модели **код симулятора**. Нативного Android readback нет; модель не получает системных полномочий.
5. Скорость обучения, начальное распределение весов, окна A/B и коэффициенты gate зафиксированы одним вариантом. Нет доказательств оптимальности или работы при других длительностях, условиях или энергобюджете.
6. Ближайшее развитие — проверка **быстрых переключений, ложных/пропущенных исходов, контекстных признаков**, сравнение с современными алгоритмами обнаружения смены режима. До победы над простыми baseline размер сети не увеличивать.

**Приёмка:** `HOST_TESTED_SYNTHETIC_ONLY`; не `ANDROID_BUILT`, не `DEVICE_VERIFIED`, не `PRODUCTION_READY`. Производственные веса UNO не обучались. GitHub, прошлые архивы, main, GitHub Actions не менялись.
