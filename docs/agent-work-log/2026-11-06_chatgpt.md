## Как вести журнал

- **Новая операция — новая запись.** Указывать: где, что вызвано/сделано, фактический ответ, где увидеть доказательство, что осталось непроверенным.
- Статусы: **OBSERVED** — ответ инструмента виден в текущем разговоре; **REPLAYED** — повторно запущен код и сохранён вывод; **RECONSTRUCTED** — установлен по старому файлу, но оригинальную последовательность действий восстановить нельзя; **FAILED** — попытка завершилась ошибкой; **NOT_DONE** — действие не выполнялось.
- Для кодовых изменений записывать ветку и commit SHA; для тестов — команду, exit code, raw stdout/stderr и хеш артефакта. Отсутствие доказательства явно отмечать.
- Не записывать намерение как результат. Не восстанавливать задним числом несуществующие вызовы инструментов. Исправления делать новой записью с указанием ошибочной, а не незаметным переписыванием истории. Время отдельной операции не придумывать, если инструмент его не зафиксировал.
- GitHub, локальный каталог и интерфейс ChatGPT — **разные источники**. Сведения из файлов и пересказов не заменяют проверку текущего состояния GitHub.
