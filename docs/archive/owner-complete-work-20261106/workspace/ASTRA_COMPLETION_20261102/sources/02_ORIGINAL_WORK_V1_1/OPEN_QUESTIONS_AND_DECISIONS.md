# Открытые вопросы и безопасные проектные дефолты

Не требуют остановки текущего математического проектирования; ограничивают дальнейшие claims/реализацию.

| Вопрос | Почему нельзя закрыть формулой | Рекомендация / дефолт | Цена решения |
|---|---|---|---|
| Какие задачи и качество обязательны? | Без Q_j,q_j feasible-set размера не задана | Сохранить все функциональные направления; перед обучением зафиксировать RU task battery | Может оказаться, что семейство не подходит |
| Сколько RAM/latency/энергии доступно A52? | Backend и ОС не измерялись | d=1024 расчётная точка, 512–2048 сравнение; никаких claims о телефоне | Данные нужны до выбора production d |
| Какие corpus/compute доступны для новых весов? | Их нет в пакете | Новая инициализация, лицензированные данные, task-balanced mix | Полное обучение может быть дорого |
| Насколько жёсткая контракция допустима для языка/планов? | Устойчивость не равна expressiveness | γ=.9 как сертифицируемая гипотеза; сравнить с finite-K bounded unconstrained baseline | Возможна потеря long-horizon reasoning |
| Достаточен ли STFT-DSP TTS? | Путь синтеза определён, intelligibility неизвестна | Не заявлять готовый русский голос; оценить и при необходимости пересчитать общий обучаемый decoder | Может добавить веса и энергию |
| Как защищён ν от rollback на Android? | Threat model и storage primitives не выбраны | Failclosed; не восстанавливать ν из snapshot | Не все устройства дают абсолютную hardware anti-rollback гарантию |
| Что значит независимый readback для каждого verb? | Разные API имеют разные наблюдаемые последствия | Capability/schema whitelist с UNKNOWN по умолчанию | Некоторые полезные действия останутся непроверяемыми |
| Какой риск/coverage приемлемы? | Это продуктовое решение владельца | До задания чисел — никакого допуска качества/энергии | Нельзя вывести commercial readiness |
| Нужен ли causal online learning? | Обычные журналы confounded | По умолчанию prediction verified completion, causal claims только на controlled стенде | Ограниченный вывод об эффективности действий |
| Какой μ для P, память и retention? | Stability bounds не определяют оптимальный retention | Row-L2 cap, проверенные записи, bounded replay; zero-forgetting не обещать | Данные определят полезную ёмкость |
| NCR-EVO заслуживает затрат? | Нет A/B/C/D | Оставить за пределами production; измерять полный поиск | Возможен отрицательный результат |
| Где абсолютная граница формальных гарантий? | Произвольное самопрограммирование не верифицируется универсально | Typed bounded DSL; immutable G_const | Теряется неограниченная expressiveness |

## Решения, уже принятые только для расчёта

Единый F; новые Θ; P отдельно от authority; runtime без NCR-EVO; d1024,b64,χ4,J2,m128,V32768; Kmax8; finite queues и quotas; model-version migration для M; failclosed restore; receipt/attribution раздельно. Это предложения автора, а не выполненная реализация и не утверждённые владельцем production-параметры.

## Что честно закрыто, а что остаётся блокером

Формулы, размерности, локальные градиенты, conditional safety/resource/stability proofs, контрпримеры и проверяемая постановка будущего эксперимента закрыты в пределах данного пакета. Нельзя доказать из приложенных источников достаточный интеллект, минимальный d, реальное энергопотребление, надёжность native-readback и преимущество NCR-EVO. Работа не маскирует эти блокеры количеством host-тестов.

Для implementation manifest до кода фиксируются: G_cap,δ_halt,λ auxiliary heads, raw endpoint normalization, номера схем и точные privacy/data retention квоты. Расчётные defaults scheduler/archive/quotas уже заданы в02 §9 и06 §9. Их изменение не допускает менять safety-инварианты. Owner-intent в natural language не считается формально доказанно интерпретированным; typed capability/confirmation отражены в02 §4.
