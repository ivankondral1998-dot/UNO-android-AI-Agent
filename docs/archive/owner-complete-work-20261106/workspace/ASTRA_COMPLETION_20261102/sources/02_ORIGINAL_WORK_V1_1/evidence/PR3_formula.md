# UNO — формальная спецификация математического эталона v0.1

**Дата:** 2026-11-01  
**Статус:** `HOST_MATH_REFERENCE`. Это конкретная проверяемая реализация формулы, **не окончательно доказанная универсальная архитектура, не Android-приложение и не общий интеллект**.

Исследовательская формула UNO охватывает **весь агент**: восприятие, отбор вычисления, общую рекуррентную динамику, прогноз/решение, внешнее разрешение, независимую проверку и локальную пластичность. Здесь первая математическая конкретизация с точными конечномерными условиями. Граф и веса фиксированы для этой версии; рост структуры NCR-EVO не реализован. Исторические веса JNO не импортированы.

## 1. Строго определённые объекты

- `n,d,a ∈ {1,…,64}`: числа входных каналов, скрытых координат, предложений действий.
- `x_t ∈ R^n`, все компоненты конечны и `|x_i| ≤ 10^6`; `h_t ∈ [-1,1]^d`; `P_t ∈ [-p_max,p_max]^(a×d)`.
- Новые веса `Θ=(W_e,W_h,W_z,W_o,b_e,b_h,b_o)`, формы соответственно `(d,n), (d,d), (d,d), (a,d), d,d,a`. Все параметры конечны по модулю не более 10.
- `B_t ∈ {0,…,1_000_000}` — бюджет *посчитанных матрично-векторных MAC*, **не джоулей**. Дробные бюджеты и `bool` отклоняются.
- `ρ∈[0,1]`, `δ∈(0,1]`, `τ∈[0,1)`, `η∈(0,1]`, `λ∈[0,1)`, `p_max∈(0,10]`, `K_max ∈ {0,…,16}`, `ε=10^-8`.
- `Π_c(u)=min(c,max(-c,u))` поэлементно; `σ(v)=1/(1+exp(-v))`; `⊙` — поэлементное произведение.

## 2. Вычислительная политика и событие

При нулевом наблюдении `x_t=0` либо `B_t<C_0` вычислительный путь *не исполняется*, предложение отсутствует, состояние `h,P` неизменно. При любой новой валидной записи наблюдения старое предложение отзывается. Устройство/ОС могут расходовать энергию на фоне — эта модель это не учитывает.

Для ненулевого входа и бюджета `B_t≥C_0`:

```text
C_0 = d*n + 2*a*d                                    (1)
z_t[j] = tanh(Σ_i W_e[j,i]*x_t[i] + b_e[j])           (2)
m_t[j] = 1[ |z_t[j]| > τ ]                            (3)
q = Σ_j m_t[j]
C_step = 2*d*q
K_t = min(K_max, floor((B_t - C_0) / C_step))        (4), если q>0
K_t = 0                                               (4'), если q=0
h_t^0 = Π_1(ρ*h_(t-1) + (1-ρ)*z_t)                    (5)
```

`C_0`: матричные MAC кодировщика и двух считываний `(W_o, P)` для каждого действия. `C_step`: MAC только реально выбранных рекуррентных строк: `W_h h + W_z z`. Скалярные операции, функции `tanh`, создание объектов, проверка прав и системные вызовы **не входят в MAC-прокси**. Важное условие: маска должна физически исключать вычисление неактивных строк.

## 3. Один разделяемый рекуррентный оператор

Для каждого `k=0,…,K_t-1` и координаты `j`:

```text
u_(k,j) = Σ_l W_h[j,l] h_t^k[l] + Σ_l W_z[j,l] z_t[l] + b_h[j]
h_t^(k+1)[j] = Π_1(h_t^k[j] + δ*tanh(u_(k,j)))      если m_t[j]=1
h_t^(k+1)[j] = h_t^k[j]                                если m_t[j]=0
```

Это одна разделяемая `R_φ` для повторных шагов, **не** отдельные «мозги» или мосты. В текущем эталоне фиксированный граф `G=(V,E,Θ,h,P)`; исследуемая эволюция топологии отдельно. Формула ограничивает число повторений `K_t` и амплитуду состояния, но **не доказывает сходимость рекуррентной динамики**.

## 4. Решение и полномочия

```text
ℓ_t[i] = (W_o[i,:] + P_t[i,:]) ⋅ h_t^K + b_o[i]
q_t[i] = σ(ℓ_t[i])
â_t = argmax_i q_t[i]                                 (устойчивый tie: минимальный индекс)
a_t = Authorize(â_t, owner, permission, confirm, unlocked, !STOP, epoch)
```

`â_t` — *предложение*, не исполненная команда. `Authorize` — внешняя доверенная системная граница. Эталон `TrustedBoundary` лишь **симулятор** независимой границы (в одном Python-процессе он не может служить защитой от злонамеренного кода). Для реального Android она должна отдельно проверять текущее permission/STOP/epoch/подтверждение непосредственно перед выполнением.

## 5. Проверенный исход и пластичные связи

Эталонная наблюдаемая метка `y∈{0,1,UNKNOWN}` появляется только из *независимого* native readback, привязанного к однократному ticket, соответствующим action/epoch/предложению. `UNKNOWN`, отказ авторизации, STOP, устаревшая задача или повторное предъявление ticket **не обучают**.

Если `y∈{0,1}` и получено свежее подтверждение:

```text
P_(t+1)[â_t,:] = Π_pmax [ (1-λ)*P_t[â_t,:]
                            + η*(y-q_t[â_t])*h_t^K / (ε+||h_t^K||_2²) ]
P_(t+1)[i,:] = P_t[i,:]                   для остальных i
```

Только `P` обновляется online; новые параметры `W_o` в этой версии можно обучить отдельно градиентным спуском (см. раздел 7). Нет скрытого утверждения об обучении **всех** начальных весов при реальном использовании.

## 6. Доказуемые инварианты (в идеальной арифметике)

**I1. Ограничение состояния.** Из `h^0=Π_1(…)` и `h^(k+1)=Π_1(…)` для активных строк, индукцией по `k` получаем `||h_t^k||_∞≤1` при любом конечном `K_t`. Инактивные строки сохраняют уже ограниченное значение.

**I2. Ограничение пластичности.** Каждое обновление проходит через `Π_pmax`; остальные строки остаются прежними, следовательно `||P_t||_∞≤p_max` по индукции, если `P_0=0`.

**I3. Лимит MAC.** Если `B<C_0`, расход 0. Иначе при `q>0`, `K_t≤⌊(B-C_0)/(2dq)⌋`, значит `C_0+K_t*2dq≤B`. При `q=0` имеем `K=0`, расход `C_0≤B`.

**I4. Раздельные полномочия.** В интерфейсе эталона `Organism.step` возвращает предложение, не вызывает ОС. Обновление через `TrustedBoundary` возможно только после свежего ticket и readback; эта структура является **проверенным программным контрактом**, а не криптографическим или Android-доказательством безопасности.

**I5. Корректность сохранения.** Полный снимок валидируется до замены каких-либо полей; сверяются SHA-256 полезной нагрузки, параметры модели/конфигурации, размерности, границы, счётчики. Восстановление не возвращает незавершённый ticket. SHA-256 обеспечивает выявление случайных изменений, **но не аутентичность против атакующего**, способного пересчитать SHA. Атомарную запись в ФС реализовывать отдельно.

**I6. Верхняя оценка чувствительности одного шага.** `tanh` и `Π_1` являются 1-липшицевыми, поэтому при одинаковых `z,M`, `||T(h)-T(h')||_∞ ≤ (1+δ ||W_h||_∞) ||h-h'||_∞`, где `||W_h||_∞=max_j Σ_l|W_h[j,l]|`. Оценка **не даёт контракции**, потому что коэффициент может быть ≥1. В области без клиппинга для активных j: `∂h'_j/∂h_l=1[j=l]+δ(1-tanh²(u_j)) W_h[j,l]`, а для неактивных строк — тождественная матрица. На границе клиппинга производная не определена.

**I7. Эффект одного пластичного обновления.** При `λ=0`, отсутствии клиппинга и том же `h`, изменение логита выбранного действия:

`Δℓ = η*(y-q)*||h||²/(ε+||h||²)`.

Для `y=1` оно неотрицательно, для `y=0` неположительно. Это утверждение **об одном входе/действии**, не о переносе навыка, глобальной обучаемости или улучшении всех задач.

## 7. Производная офлайн-обучения новых весов

На задаче размеченных признаков `f∈R^d` обучаем `W_o` из **новой случайной инициализации** по softmax CE:

```text
p_i=softmax(W_o f)_i
L=-log(p_target)
∂L/∂W_o[i,j]=(p_i-1[i=target]) * f_j
W_o ← W_o - learning_rate * ∂L/∂W_o
```

Эта производная проверяется центральными конечными разностями. Эталонный датасет — **искусственная разделимая 2D-классификация**, не речь, планирование, смартфон и не «обучение полного организма». Архитектура полного обучения `W_e,W_h,W_z` и результатов Android пока не разработана.
