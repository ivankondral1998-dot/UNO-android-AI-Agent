# UNO vNEXT — проект для решения владельца, 06.11.2026

Статус G4 PRECODE CANDIDATE. Основа — приложенный R4.1, §§1–18 и 21–27, вместе с оригинальными R5.3 NORMATIVE/01–07. Настоящий текст задаёт два взаимоисключающих расширения этой основы. Их численные лимиты определяются в manifest до эксперимента. Сохраняются единый F, все целевые модальности и независимая Android authority. До выбора O01–O08, профиля и проверки согласованности ABI применение к продукту остаётся открытым.

## Контракт F и часы

Рабочее состояние одного экземпляра: (s,g,P,M_exact,M_sem,G,v,clock). s и g имеют формы выбранного профиля R4.1, v идентифицирует согласованный snapshot весов, графа и политики. G — ограниченные записи связей. Android доверенно ведёт отдельный журнал полномочий и квитанций. Один вход — типизированное событие с id, источником, boot/epoch, монотонной меткой и разрешённым payload. Каноническая последовательность задаётся доверенным ingress, время из payload используется лишь как данные. При чтении F получает неизменяемый snapshot и не читает будущие квитанции. WAKE ограничивает допуск вычислений, SENSOR выдаёт значение, доступность и freshness; неизвестность кодируется отдельно. Выход F — новые скрытые состояния и предложения, включая уточнение, отказ, текст/речь и план. Каждый внешний шаг плана проходит повторную независимую проверку.

S1–S4 сохраняют контракт входа, состояния, семантического чтения и выбора вычислений из R4.1. Ниже изменяется вход z в S5 либо внутренняя ветвь S5. S6 сохраняет порядок admission, K проходов, halt и бюджет. S7 выдаёт оценку исхода с P и применяет её в пределах исходного контракта. Несовместимые версии должны завершаться отказом до вычисления. Разрешённый выход получается из F через штатные головы, поэтому связи не образуют отдельную политику.

## Общая схема связей

Один логический record: (id, generation, source, destination, relation, context, support, contradiction, weight, expiry, evidence_ref). Конечные словари relation/context и границы идентификаторов закреплены manifest. Типы REQUIRES, EXCITES, INHIBITS являются гипотезами для представления, а не правилами исполнения. Context описывает наблюдаемые условия, unknown и conflict сохраняются явно. В упорядоченном индексе ключ (context,source,id); запрос получает максимум R записей, сканирует максимум Q слотов, отдаёт флаг усечения. Кандидаты на создание берутся из ограниченного набора пар наблюдаемых событий и типизированных признаков, сформированных F. Evidence id связывает запись с проверяемой историей, но не предоставляет прав. Состояния связи: proposed, observed, corroborated, contested, expired. Без идентифицирующего сравнения употребляется статус observed, даже если частота высока.

Пусть u — код условий, x — отдельно допущенное свидетельство о результате, y∈{0,1} при наличии размеченного endpoint. Проверенный шаг кандидата: w' = clip(w + η a (y−σ(w·u))u, −wmax,wmax), покоординатно, где a=1 только при независимой проверке, применимой к данному endpoint и версии. При неизвестном результате a=0, и транзакция не меняет score. Дубликат не расходует ещё один шаг. Два разных типа счётчиков для поддержки и противоречий насыщаются. Для временной релевантности на чтении применяется множитель exp(−λ age) внутри валидной эпохи. Смену boot проверяет журнал, а неизвестный возраст не считается свежим. При нехватке места вытеснение по заранее замороженному порядку (expired, затем lowest value, затем id), с защитой активных ссылок и резервом старых задач. Это кандидат расширения P для графовых записей, отдельно от действующих строк P1 и их доказательств. Семантическая коррекция владельца хранится в собственном пространстве меток и не попадает в физический endpoint loss.

## A — структурированная память, фиксированные тензоры

Для активных записей вычислить e_i = encode(type,context,src,dst,metadata) ∈ R^m детерминированным ограниченным отображением с trainable lookup только через существующий бюджет кодировщика выбранного профиля. Кодирование коллизий допустимо для summary, а exact id доступен из точной памяти. z_base = tanh(z0+W_r r). g_G = Σ_i ω_i clip(w_iᵀu_i,−1,1)e_i, где ω = softmax ограниченных scores по допущенным записям, пустой набор даёт ноль. z_A = tanh(z0+W_r(r+γ g_G)). z_A имеет ту же форму, что z_base. При γ=0 восстанавливается исходная ветвь точно. Ветви S5 остаются u=tanh(Ah+Cz_A+a), f=tanh(Bu+b), h'_j=(1−αM_j)h_j+α M_j Σ_l f_l/J. Добавочный forward O(Q+R m+R p) при прямом кодировании p признаков и существующем W_r. Стоимость индексирования, decode и чтения учитывается отдельно. В фиксированном snapshot и z_A локальная оценка по h наследуется. Обратная связь через запрос и смену маски требует отдельной оценки.

Физические tensor slots, формы и смещения профиля сохранены. Схема памяти G версионируется независимо. Старая модель без G читает пустой граф только после явной миграции и проверок parity. Нормативные caps exact и semantic R4.1 сохраняются, граф получает отдельную квоту. Запрос exact по id, generation, namespace, digest и политике согласия. Возвращаются COMPLETE / TRUNCATED / CONFLICT / UNKNOWN / DENIED по контракту R52/02. Выжимка никогда не подтверждает полноту.

## B — изменяемые рёбра внутри S5

Разбить h на n блоков размера b. На активном j добавить к предпроекции ветви v_j = A_j h+C_j z+a_j сумму Δ_j = Σ_{e:i→j} β_e T_{type(e)} h_i по допустимым для текущего snapshot рёбрам. T_r∈R^{r_u×b} общие по типам, r_u — ширина u. u=tanh(v_j+Δ_j), f и residual как в A. Нулевой набор рёбер даёт базовую ветвь. Одна итерация читает старое h для всех j и пишет новое h после вычисления активных строк, поэтому циклы однозначны. Нельзя считать операцию skipped, если ядро умножило dense блок и затем занулило результат.

Manifest B фиксирует n,b,r_u,T, максимум d_in на блок, квоту E≤n d_in, максимум replacements за транзакцию и на окно. Добавочные параметры T·r_u·b, при a активных блоках и K проходах добавочные MAC ≤K J a d_in r_u b для матриц плюс ≤K J a d_in r_u для взвешивания. Цена проверки контекста O(K J a d_in p), если контекст пересчитывается на шаге. Выбор T и размеров требует переэкспорта. Snapshot topology — фиксированные слоты CSR с максимальной ёмкостью и фактическими counts, версия графа отличается от версии схемы. Кандидат rewiring строится из наблюдаемой пары, допускается только при независимой проверке свидетельств, прохождении dev replay и ресурса. Если выделенного места нет, кандидат отклоняется либо вытесняет запись по указанному порядку. Проверка на закрытом holdout выполняется только после фиксации решения, не является условием online commit.

Для фиксированных β и z, строковая норма A+Δ по h ограничена ||A||∞+Σ|β_e|·||T_r||∞. Нормировать сумму к заранее выделенному бюджету δ, чтобы для каждой ветви ||B||∞(||A||∞+δ)≤q. Тогда tanh 1-Lipschitz даёт коэффициент (1−α)+αq для активных блоков и 1 для прочих в общей sup-норме. При q<1 и общей маске all-active получается сжатие. При смене дискретного выбора доказательство не переносится. β с зависимостью от h требует добавочного члена или фиксации на весь unroll. Смена графа публикуется после атомарного commit, между задачами, с rollback на предыдущий совместимый snapshot.

## Данные, обучение и независимость наблюдений

Pretrain на локальных лицензированных данных. Набор пока REQUIRES_DATA. Требуется журнал происхождения, право обучения и распространения производных весов, согласие на частные записи, версии нормализации и токенизатора. Не смешивать чужие корпуса с наборами оценки. Разделять по говорящим, парафразным семействам, контекстам, сессиям и устройствам. Train включает oracle pool для mask/halt, dev — настройку, calibration — пороги уверенности, locked — однократный независимый экзамен. Набор для принятия пластического шага не является locked.

ASTRA_03 L3a: J(Θ;μ)=E[Σ_k λ_k L_k + 1−U_Z(τ) + λ_c C/C_ref + Σ_j μ_j 1[Z=j]/π_j·(A(τ)−(1−c_j))]. π_j>0, A отмечает недопустимую незавершённость, U независимая task utility. Supervised masks известны до выбора K. UNKNOWN маскируется для физической метки, остаётся в учёте покрытия. Dual μ_j ← max(0, μ_j+η_μ mean(1[Z=j]/π_j·(A−(1−c_j)))). c_j задаёт per-class coverage, не общую accuracy.

L4 для upstream d_j: d_v=α M_j/J·d_j⊙(1−f²), d_u=(Bᵀd_v)⊙(1−u²); ∇B=d_v uᵀ, ∇A=d_u hᵀ, ∇C=d_u zᵀ, biases d_v,d_u; обратное h=(I−αD_M)ᵀd'+Σ Aᵀd_u+∂L_k/∂h. В B дополнительно ∇T_r += β d_u h_iᵀ, ∂h_i += β T_rᵀd_u на каждой выбранной ветви. В A градиент идёт через W_r и смесь записей: ∂score_i=ω_i · upstreamᵀ(value_i−mean). Detached history не обучает key/value writer, нужны пары запись→будущий запрос внутри unroll. Цепное правило суммирует shared usages.

L5: ∇E[L]=E[∇L+(L−b)∇logπ_Θ(τ)]. Учитывать wake, маску, hazard и другие sampled decisions, включая rewiring только если он действительно семплируется с записанным законом. Teacher-forced labels не sampled. Baseline зависит от истории до решения и detached. Hard gate, deterministic topology change, projection, TBPTT и STE не становятся точным градиентом. Offline P=0 и fixed topology на сегменте; online только ограниченный P и отдельный record update под проверенную метку. Holdout повторно используется только как открытый диагностический набор. Loss reduction на finite replay ограничивает наблюдаемые старые примеры, не гарантирует population retention. NCR-EVO предлагает bounded sandbox варианты, ведёт отдельные версии и fresh holdout, не получает capability.

## Будущий полезный экзамен

Фразы для on/off/status, отрицания, отмены, неоднозначности, отсутствия камеры, чужой команды и отказа. Оценка понимания и transfer отдельно от допущенного действия. Набор фраз должен требовать learned semantics и сочетания с контекстом, а тестовые шаблоны и говорящие отделены от train. Эксперимент с фонариком после отдельного допуска: состояние до команды, typed proposal, конкретное согласие с TTL, повторная проверка boot/epoch/permission и STOP в точке линейризации dispatch, нативный вызов, независимая аппаратная фиксация света и OS callback. Callback может подтвердить наблюдение, но не установить причинный эффект при конкурирующем приложении или исходно включённом свете. Контроль no-dispatch, конкурирующее действие, незавершённый ответ, stale callback, revoke, kill/reboot, STOP до/после отправки. Поздний эффект после dispatch учитывается как такой. При UNKNOWN запрещён blind retry. Owner correction меняет intent label; verified receipt обучает прогноз эффекта; измерение сенсора идёт отдельным каналом; consent управляет доступом. Сравнить старые навыки до и после адаптации и после рестарта, проверить fresh unseen utterances. Без измеренного физического оракула статус REQUIRES_DATA.

## ABI, сохранение и цена

Нормативная база тензоров и статусов — R4.1 §§15,21–23 и R53 ASTRA_02/05. Добавочные record поля: u64 id, generation, expiry, evidence ref; u32 src,dst,context; u16 relation,flags; u32 support,contradiction; p float32 weight. При LE и выравнивании 8 record stride align8(56+4p), без нативного padding. Дополнительно отдельно учитываются индекс, blob evidence, staging copy, журнал, mmap/page residency и временный workspace. Для B T хранится как отдельный little-endian float32 массив T×r_u×b в исследовательском ABI. Декодировать finite values, caps, индексы, schema/digest до публикации. Неизвестная версия не исполняется. Размеры и квоты manifest не выбираются без O03/O08; RAM peak включает одновременно старый, новый snapshot, buffers, JNI и Android runtime. Нагрузка измеряется p95/p99, peak PSS, idle, joules/completed-task, thermal soak, offline trace с учётом SAF, а не через MAC.

Сохранение через версионированный атомарный snapshot с journal и idempotent receipt commit. STOP/dispatch и receipt/P/M/G имеют раздельные проверяемые точки commit. После сбоя восстановить согласованную версию, replay только локальных идемпотентных записей и пометить незавершённый внешний эффект MAY_HAVE_EXECUTED. Выданные capability не восстанавливаются из M/G. Отключение/фон/перезапуск, отсутствие датчика, thermal throttle и backpressure возвращают явные статусы. При недостаточном ресурсе не снижать coverage незаметно. Аудио, planning, exact retrieval и privacy остаются частью базового каркаса R4.1. Разделение по назначению данных, локальная обработка, удаления по согласию и ограничения распространения входят в G6.
