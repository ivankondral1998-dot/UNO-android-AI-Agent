# UNO Work vNEXT-R4 — предзапись проверки W-R4-01

Дата 06.11.2026. Один локальный процесс Python, до 30 секунд и 256 MiB виртуальной памяти. Код ниже служит для анализа документов и точечных функций исторических фикстур. Без компиляции native, процессов Android, обучения и изменения оригиналов.

Входы: восстановленные блоки V14/V19/V20 из V01–V20 rev2, SHA-256 сверены по индексу контейнера. Для N0-07 входом служит реконструированный Stage 5 CSV из efdb1767ef75cbdb04ff813323c107c3bd22c4b6. Полный CSV с телефона отсутствует.

Критерии, зафиксированные перед запуском:

| Тест | Ожидаемое наблюдение и предел |
|---|---|
| V19 исходные 14 виртуальных сценариев | Все исходные сценарии проходят при вызове только функций Scheduler/scenario. Это ограниченный host replay. |
| V19 OWNER, очередь опустела | Остаточный outbox остаётся, issue=0. Контрпример к переносу виртуального PASS на S2 ready-microstep. |
| V19 OWNER → BOOT | До epoch-проверки старый outbox выдаётся. Synthetic request, физического эффекта нет. |
| V14 плохая типизация | range с числами на строковом time_scope проходит validate_query, чтение выдаёт TypeError. |
| V14 изменённый cursor.next_slot | В валидном snapshot можно подставить next_slot=4 и получить пустой COMPLETE, пропустив записи. |
| V20 два commit с одним свежим token | Оба ACCEPTED, счётчик 2. Scope V20 не включает дедупликацию action tickets. |
| V20 STOP | Старый token после STOP даёт REJECTED_STALE. |
| N0-07 Stage 5 | Ровно 80 строк, метки 77/3/0, три перехода, все прогнозы MOVE, 77/80 у F, persistence и Markov. |
| Арифметика | Комбинации масок, ΔB для C256R32, pmax и S7, Hoeffding; значения независимо пересчитываются. |

Negative fixtures ожидают воспроизвести дефект/непокрытое свойство. Они не понижают первоначальные узкие PASS исходных сценариев.
