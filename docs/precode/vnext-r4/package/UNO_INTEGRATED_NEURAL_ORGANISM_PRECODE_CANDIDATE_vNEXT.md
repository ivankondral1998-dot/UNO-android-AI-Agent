## 1. Полное состояние и один исполнитель

Это условная минимальная архитектура из R4.1 §23 при A_cap/A_tx/A_fs. Конкретный Android backend и lifecycle определят число системных компонентов. Jarvis/JNO — источник сравнения локальных Android механизмов после проверки происхождения/лицензии. Новые веса UNO, а не перенос старых весов. ## 2. Время, передача заявки и атомарность

По ASTRA_01 S2/S3 $K_{race}(dw',d\Delta,d\eta\mid w,S,T,R,u_R)$ допускает $0\le\Delta\le d_R$ до ближайшего ready/deadline/timer. События и изменение мира совместны. Event time источника и trusted ingress time различны; поздний пакет не откатывает причинные часы. Для доступных событий на одной метке порядок STOP/REVOKE/DEATH/BOOT → DEADLINE → READBACK → OWNER → SENSOR → INTERNAL, затем serial. Ready с $d_R=0$ требует bounded microstep даже при пустой внешней очереди. Внутренний ранг ресурсов убывает при конечных cap и справедливом планировщике. Это не верхняя физическая задержка на Android.

В S2 аргумент u_R означает только выпущенный handoff предыдущего δ. PREPARED находится в отдельной pending части R. Выпущенный u_R потребляется один раз даже без нового внешнего наблюдения. Если due отсутствует и никто не поступает, реактор ожидает, а не исполняет бесконечные пустые microsteps. Любой ready step списывает конечный fuel, даже при отказе.

R4 явно разделяет PREPARED и линеаризацию handoff. В R4.1 авторизация outbox уже считалась линеаризацией. Здесь pending outbox до handoff ещё можно отклонить. Эта кандидатная замена действует только для нового профиля.
1. Контроллер делает durable PREPARED: уникальный ticket, digest аргументов, task/goal, allowed effect, model/feature schema, source generation, boot/$\nu/e$, expiry, frozen h_a. Ставит READY_SEND due=now. Pending старого boot, consent или epoch не восстанавливается как исполнимый.
2. Линеаризация D: в том же trusted порядке, что STOP, проверить актуальные identity/consent, scope, permissions, prestate, deadline, budget и unused dispatch. Атомарно по этому порядку передать одноразовый handoff каналу исполнения. Канал может передать запрос ОС позже. Повторное изменение прав ОС или ошибки ресурса дают отказ/UNKNOWN по факту. Сеть, DSL и веса не меняют gate.
3. Авария после PREPARED с незавершённым исходом → MAY_HAVE_EXECUTED. Безопасный повтор только по новому intent/билету и fresh precheck. Никакого blind retry. OS return отдельно от native postcondition.
4. Линеаризация C: в том же порядке проверить живые epoch/consent/STOP, срок, schema, source generation, неизменяемый trace, admissible label и unused ticket. Атомарно сохранить used + receipt + P[a] + ссылки на допустимые M/G либо ни одной записи обновления. Защитить транзакцию от stale P/graph version через CAS и повторную валидацию, либо отклонить. При неполной или UNKNOWN квитанции не вычислять градиент с неопределённым y. Допустим отдельно разрешённый diagnostic late observation без P/M/G-кредита.
5. STOP latch вне neural queue. ACK после запрета новых handoffs и сохранения требуемого fail-closed состояния. REVOKE/BOOT инвалидируют ready/timers/cursors. Прерывание после D не отменяет OS effect. Storage failure не даёт подтверждение успешной остановки или автоматическое восстановление старого допуска.

При A_cap/A_tx/A_fs STOP<D исключает D. D<STOP<C исключает C, физический результат может уже существовать. C<STOP сохраняет committed state. Доказательство состоит в проверке единственного общего порядка; проверка latch до отдельного несериализованного commit недостаточна. P128 fresh nonce препятствует оживлению старых tickets с вероятностной границей, без полного anti-rollback. Хеш текущих байтов не устанавливает свежесть.

## 4. Точная память и три происхождения опыта

ASTRA_04/R52/02. Raw bytes ограничены отдельным store; $k=\tanh(W_kh)$, $v=\tanh(W_vh+f_e)$ по m-мерной схеме (R4.1 §21.1). FP16 key/value, signed model/schema digest, slot+generation, source/scope, consent epoch, boot/timebase, TTL. Пара v,-v при равных весах даёт ноль. Semantic r только SUMMARY_ONLY; исходные записи и противоречия проверяются exact. Сумма и прошлый факт не подтверждают состояние ОС сейчас.

RetrieveExact(query,scope,k,budget) валидирует тип и операторы каждого поля до поиска. Например time_scope: enum eq/in; monotonic range: только числовые значения одного boot/timebase. Неподдерживаемый ввод возвращает typed INVALID_QUERY. Доверенный контроллер фиксирует snapshot и eval_time. При выдаче и использовании снова проверяются consent, версия, срок и provenance. DENIED без защищённых байтов, UNKNOWN при недостоверной целостности/источнике/канонизации, TRUNCATED если cap k/scan budget превышен, CONFLICT после исчерпывающего сертифицированного scan и возврата всех релевантных конфликтующих записей внутри k, COMPLETE только после полного валидированного scan без конфликта. Неосмотренная часть может изменить вывод; conflict_seen и matched_lower_bound имеют нижнеграничный смысл.

Continuation — непрозрачный handle в ограниченной trusted таблице. Привязка к digest запроса, scope, k, snapshot, eval_time, boot/consent/model, сроку, позиции и уже проверенному префиксу. Вход не задаёт позицию. При budget truncation можно накопить полный proof на том же снимке если matches≤k. Если matches>k, исходный запрос остаётся TRUNCATED; COMPLETE требует нового авторизованного запроса с подходящим k. После invalidate высвободить pinned refs, обход новой версии с новым согласием. Проверка hash на байтовую порчу не является аутентификацией при противнике, умеющем заменить данные и hash.

В F сходятся три источника с разными целями:
| Событие | Допустимая метка | Предел права |
|---|---|---|
| OWNER_TEACHING | Версионированные intent, explanation, correction, ссылка на высказывание/решение | Уточнение смысла. Прежнее объяснение не разрешает будущий вызов ОС |
| SENSOR_OBSERVATION | Типизированное value/missing/quality и source time; для прогноза sample после freeze | Физическое наблюдение в указанном окне. MODE A/B — контекст |
| ANDROID_OUTCOME | Независимый verified binary postcondition для уникального ticket/verb, before/after и attribution | Обновление P только по P1. API return, UNKNOWN и hard censor не дают Y |

Исходные label, модель/схема и frozen features проверяются в одной транзакции. Подлинное утверждение владельца может опровергнуть прежнюю разметку смысла, сохранив provenance. Оно не переписывает сенсорную истину. Исторические эмбеддинги/ P старой Θ помещаются в quarantine при миграции. Нужны raw re-encode и проверка при новой модели. Атомарный pointer, authenticated known-good slot, bounded WAL и аварийный режим R4.1 §11.2 сохраняются. Отзыв записи инвалидирует зависимые refs; P/G, у которых отозванная запись использована в credit, сбрасываются или пересчитываются по ещё допустимому журналу в рамках квот. Удаление raw само по себе не доказывает exact unlearning Θ. При полном разрушении reference возможны два разных оригинала с одним остатком: полное восстановление без side information не доказуемо.

## 5. Два кандидата структурных связей

Оба используют существующие F и контроллер, исследуются раздельно. A — запись связи в M/G, фиксированный tensor ABI. B — новый ABI оператора, конечные слоты рёбер внутри S5. B требует явного исключения из freeze runtime topology S1. Θ в обоих arm остаётся фиксированной при online, в B это включает матрицы типов рёбер. Рост числа нейронов и произвольная мутация Θ относятся к отдельным исследовательским E1/NCR и новому manifest/валидации, их не вводит запись ребра.

### 5.1 Состояние связи, образование и обновление

Запись: id/generation, src/dst и поколения концов, relation (REQUIRES/EXCITES/INHIBITS как структурные **гипотезы**), context и source domain из manifest, evidence_ref, boot/consent, observed/expiry, state и support/contradiction, $w_e\in[-w_{max},w_{max}]^p$. Stable typed IDs и валидная схема. Детерминированный ограниченный Ctx(z0, event) задаёт список до c диапазонов индекса и векторы $u_e\in\mathbb R^p$, $\|u_e\|_2\le U$. Маппинг полей, клип, max bytes и версия фиксируются перед опытом. Источник, пользовательская идентичность и trust извлекаются из envelope контроллера. Контекст не становится capability. Для B src/dst — индексы блоков, а evidence содержит привязку пары признаков/событий к этим блокам по фиксированной карте. Из наблюдений без идентифицирующей интервенции направление causal action не устанавливается.

Два уровня. Кандидат пары возникает из ограниченного набора размеченных или наблюдаемых $src,dst$ с известными context/target. Допуск: совместимая версия, законные источник/согласие, цель, max births/evictions per batch и storage; исходный stamp immutable. Поддержка/противоречие считаются по endpoint/label данной схемы. Если одинаковый контекст даёт несовместимые labels — CONTESTED, оба evidence сохраняются до политики retention. Contested не даёт causal certificate, допустимость участия в F задаёт manifest и проверяется абляцией. CORROBORATED означает поддержку по замороженному правилу проверки источников, причинная атрибуция остаётся отдельной. При TTL, отзыве, смене схемы, incompatible boot или противоречивой валидации запись исключается из live eligibility. При заполнении — expired → minimum declared retention score → id, с pinned/старым резервом и atomic publication. Все pinned → CAPACITY_REJECTED.

Для каждого допущенного y∈{0,1} и предшествующего outcome замороженного u:
$$p_e=\sigma(w_e^T u),\quad w_e^+=\Pi_{[-w_{max},w_{max}]^p}(w_e+\eta(y-p_e)u).$$
При UNKNOWN/duplicate/STOP/stale/неверном source/consent update тождественен до вычисления. Дедуп по canonical evidence id + relation identity в той же транзакции, что счётчики и w. Расширение W_G имеет свой шаг, P1 отдельно. Для $ℓ=\log(1+\exp(w^Tu))-yw^Tu$ Hessian≤$U^2/4$ по спектральной норме. Если $U>0$, $0<\eta\le8/U^2$, то $\ell(w^+)\le\ell(w)-(1/\eta-U^2/8)\|w^+-w\|_2^2$. Из гладкости и оптимальности проекции. При η=0 или u=0 шаг identity. Это снижение loss одного frozen примера. Последовательность конфликтующих целей и eviction не наследуют retention. Кандидат rewire валидируется на dev replay с cap роста, old strata, budget и failure rollback. Locked экзамен после freeze и отдельно от online commit.

### 5.2 A — структурированная память перед S5

Из frozen z0 и typed context, scan≤Q_G slots, допуск≤R_G, deterministic order. Для живого e задать $e_e\in[-1,1]^m$ фиксированным signed feature hash по stable typed relation key, не по меняющемуся весу/возрасту. Коллизии намеренны, exact сохраняет идентичность. $ℓ_e$ — bounded score relevance из z0 и схемы с явным manifest, не зависит от w_e в этом подварианте. $d_e=\exp(-\lambda age_e)$ с $\lambda\ge0$ и валидным boot. $age_e$ определён доверенными часами; stale исключён. Decay умножает value вне softmax, поэтому одинокая запись тоже затухает.
$$g_G=\sum_e\omega_e^G d_e\,\mathrm{clip}(w_e^Tu_e,-1,1)e_e,\quad
\omega^G=\mathrm{softmax}(\ell),\quad z_A=\tanh(z_0+W_r(r+\gamma g_G)).$$
Пустой G или $\gamma=0$ (обход до чтения) даёт baseline алгебраически. h0, S6 и C z принимают z_A. $‖g_G‖_\infty\le1$ по выпуклой сумме. Fixed snapshot и z_A дают прежний W4 fixed-z; изменяемые eligibility и mask остаются разрывами. Отдельный memory write не приписывает победу общему F без ablations. Один matvec W_r остаётся. Forward graph work $O(c\log(E+1)+Q_G+R_G(p+m))$ плюс чтение/проверка байтов и bounded Ctx. Сортированный массив insertion/staging $O(E)$; дорогой update оплачен. Полный top-R вне просканированного диапазона не утверждается. Алгебраическая parity и bitwise parity различаются.

### 5.3 B — разреженная добавка внутрь S5

Для e:i→j, $T_r:[r_u,b]$ общий по relation type, $r_u=\chi b$. Коэффициент $α_e=\mathrm{clip}(w_e^Tu_e,-1,1)$ до S5. В manifest $\|T_r\|_\infty\le t_r$, decoded bound проверяется. $S_j=\sum_{e\to j}|\alpha_e|t_{r(e)}$. $c_e=\alpha_e\min(1,\delta_j/S_j)$ при S_j>0, иначе $c_e=\alpha_e$ (при S_j=0 все ненулевые коэффициенты имеют нулевой T). z, c_e, eligibility и slots фиксируются на событие. Вариант
$$\Delta_j(h)=\sum_{e:i\to j}c_eT_{r(e)}h_i,\quad u_{lj}=\tanh(A_{lj}h+C_{lj}z+a_{lj}+\Delta_j(h)).$$
$Δ$ вычисляется только в активных j и один раз на j,k для всех l. Пустой граф — baseline. Сумма в каноническом порядке id. Индексы bounded, $E_B\le n_b d_{in}$, не больше d_in рёбер на destination. Record swap публикуется между событиями атомарно с audit/quota, отмена версии через verified snapshot pointer, без изменения permissions. Ни ограниченная память, ни насыщаемые support counts сами не доказывают улучшения. Перед публикацией проверяются STOP, текущая версия и consent.

$\|\Delta_j(h)-\Delta_j(h')\|_\infty\le\delta_j\|h-h'\|_\infty$ по сумме норм. $κ_j=\max_l\|B_{lj}\|_\infty(\|A_{lj}\|_\infty+\delta_j)$. Общая маска даёт $c_M=\max_j[1-\alpha M_j(1-\kappa_j)]$. При 0<α≤1, all-active и $κ_j<1$ сжатие, при inactive хотя бы один коэффициент 1. Для A_cap=1 и B_cap=.9 требование κ≤.9 оставляет δ=0; пример δ=.05 и A_cap=.95 сохраняет κ≤.9, либо при A_cap=1 получается κ=.945 и c_full=.9725 для α=.5. Это выбор norm budget, не гарантированное качество. Для LR2 bound нормы применить к произведению факторов. Для общей последовательности полный sweep при фиксированном z/F и $κ_j\le\kappa<1$ уменьшает sup-разность пары не более чем $1-\alpha(1-\kappa)$, если обновлён каждый блок: ни один шаг не увеличивает исходную границу, после первого посещения координата сохраняет меньшую границу. Случайные K≤8 не гарантируют sweep.

Для двух графов при общем z, h0 и path масок определим $D_G=\max_j\|G_j^{new}-G_j^{old}\|_\infty$ для операторов Δ_j. Тогда при $\|h\|_\infty\le1$
$$e_{k+1}\le c_{M_k}e_k+\alpha\max_{lj}\|B_{lj}\|_\infty D_G.$$
Итерация: $e_K\le\alpha B_{max}D_G\sum_{i<K}\prod_{j>i}c_{M_j}$. При фиксированном partial c=1 это $\alpha B_{max}D_G K$, не деление на ноль. Проверять decoded T/norms. Общий для двух траекторий bound не сертифицирует разные hard selectors, изменение z через feedback или замкнутую устойчивость организма. Возможны jumps через decision boundary при произвольном малом возмущении. Конструкция fail-closed не зависит от этой оценки.

## 6. Обучение, P и честная оценка удержания

Путь offline: зафиксированные group splits и raw→target transformations, T0 валидация формата/прав/DSP, T1 совместное representation training текста/звука/экрана, T2 цели/args/verified outcomes и пары write→future read, T3 oracle selector/halting, T4 projection/QAT/export/calibration. Настоящее обучение продукта требует данных и отдельного разрешения. При исследовательских малых кандидатах действует разрешение и пределы от 05.11 из AGENTS/UNO_LAB_AGENTS, результаты отдельно от G4. Ни в одном профиле этой редакции веса не обучались.

**L3a (ASTRA_03 §1a).** Z — заданный до действий класс issued task, $\pi_j=Pr(Z=j)>0$, A=1 при необоснованном незавершении, U_Z∈[0,1] — независимая utility. Разметка заранее определяет, где корректное уточнение/отказ является выполнением. $C_{ref}$ — объявленная dense K8 цена для сопоставимой длины. Нулевой cost у пустой траектории не убирает L_task. Полная задача:
$$J(\Theta;\mu)=E\left[\sum_i\lambda_i L_i +(1-U_Z)+\lambda_c C/C_{ref}+\sum_j\mu_j\frac{1[Z=j]}{\pi_j}(A-(1-c_j))\right].$$
$g_j=B^{-1}\sum_b 1[Z_b=j](A_b-(1-c_j))/\pi_j$, $\mu_j\leftarrow\max(0,\mu_j+\eta_\mu g_j)$. Математическая подстановка даёт $E[1[Z=j]A/\pi_j]=E[A\mid Z=j]$, поэтому coverage по классу. Класс без данных остаётся REQUIRES_DATA. Порог и dual fixed на Θ-step. Конечность/сходимость политики не выводится из формулы. Supervised masks заранее зависят от данных, а не от halt/отказа. Два наблюдателя для неоднозначной semantics, независимый native oracle для физики. Строки глаголов вне каталога и endpoints frozen zero вместе с optimizer state, source identity по схеме.

Потери R4.1 §10/ASTRA_03: AR teacher CE, canonical grounding/goal DSL/verb+args CE, наблюдаемость BCE только uncensored, outcome BCE только verified Y, masked belief128, CE нужного retrieval, future-answer после differentiable write, CTC, TTS L1 log spectra + stop BCE, value squared error, risk/conf/wake metadata/halt BCE, old replay+KL. Acoustic wake и SENSOR требуют отдельные допустимые разметки, произвольные сторонние метки не подставляются. Нет истинного label у UNKNOWN. TTS target и decoder clipping используют тот же спектральный формат; конкретный DSP см. R4.1 §12.2. Candidate loss scale/caps и качество по стратам из training manifest. Затраты: $F_{train}\approx6\sum_e N_e C_e+F_{DSP}+F_{optimizer}+F_{oracle}+F_{recompute}$, Adam16P или 18P с BF16 copy плюс activation/backend; не сравнивать с peak FLOPS или runtime PSS.

**L4.** Для $d_j=\partial L/\partial h'_j$:
$$d_v=(\alpha M_j/J)d_j\odot(1-f_{lj}^2),\qquad d_u=(B_{lj}^T d_v)\odot(1-u_{lj}^2),$$
$$\nabla B=d_vu^T,\ \nabla b=d_v,\ \nabla A=d_uh^T,\ \nabla C=d_uz^T,\ \nabla a=d_u.$$
$\bar h_k=(I-\alpha D_M)^T\bar h_{k+1}+\sum_{lj}A_{lj}^Td_u+\partial L_k/\partial h_k$, $\bar z=\sum C^Td_u$ плюс другие consumers. B добавляет $c_e T_r^Td_u$ к $\bar h_i$ и $c_ed_u h_i^T$ к $\nabla T_r$ для каждого use. Если $c_e$ строится из дифференцируемого z0, прибавить $\langle d_u,T_r h_i\rangle\partial c_e/\partial z_0$ и paths к w/u, либо явно задать detached context в offline objective. Bound $t_r$ — константа manifest, поэтому само нормирование не даёт производной по T. На clip/tie границах объявить subgradient или separate discrete rule. BPTT суммирует по k,t,l,j; factorized A=LR даёт $\nabla L=d_u(Rh)^T,\nabla R=(L^Td_u)h^T$. Tied embeddings суммируют scatter lookup и gradient output. CTC $\partial L/\partial l_{fk}=p_{fk}-\gamma_{fk}$ с occupancy posterior по допустимым выравниваниям и правильным collapse repeats до удаления blank.

В A $\bar g_G=\gamma W_r^T[\bar z_A\odot(1-z_A^2)]$; при $v_e^G=d_e\mathrm{clip}(w_e^Tu_e,-1,1)e_e$, $\partial L/\partial\ell_e=\omega_e^G\bar g_G^T(v_e^G-g_G)$. Value path $\partial L/\partial w_e=\omega_e^G d_e(\bar g_G^Te_e)1[|w_e^Tu_e|<1]u_e$ при независимости score от w_e. Если score зависит от w, нужен также score path. Для обычного semantic r формулы с $\omega_i\bar r$ и $\omega_i\bar r^T(v_i-r)$, затем $k_i/(\sqrt m T_M)$ по q. Detached old embeddings не обучают key/value writer. Нужны пары внутри unroll или replay из raw.

**L5.** При фиксированном допустимом support и differentiable law:
$$\nabla E[L]=E\left[\partial_\Theta L+\sum_t(L-b_t(H_t))\partial_\Theta\log\pi_\Theta(a_t\mid H_t)\right].$$
$H_t$ — история до соответствующего choice, baseline detached. Conditional expectation score равен нулю. Допустим cost-to-go если исключённые члены измеримы до choice. Не вычитать b_t из score всей траектории: при a1∼Bernoulli(p), b2=a1, L=0 получается паразитный $-p(1-p)$. Включать sampled wake, prefix, hazard и on-policy args/verbs; teacher forcing и forced actions не дают score. L5 по непрерывной части ограничен выбранным objective и support, QAT/STE, TBPTT, hard selection и смена eligibility не объявляются точной производной. P=0 на всём offline segment. Использовать прежнюю P от отдельной frozen Θ как fixed replay либо дифференцировать весь update, если будет разрешён отдельный meta-objective. Пересчёт текущей P с detach был бы semi-gradient.

**P1 (ASTRA_04).** При свежем admissible binary endpoint, frozen h=h_a и текущем p=P[a] задать $d_h=\varepsilon+\|h\|_2^2$, $q=\sigma(l_0+p^Th)$,
$$p^+=\Pi_{\|p\|_2\le1}\{p-\eta[(q-y)h/d_h+\lambda p]\}.$$
Запрет других строк и атомарность used сохраняются. L≤.25+λ, projection даёт P2 descent на BCE/d_h+λ‖p‖²/2 для фиксированного примера. Для Θ/canonical features не изменённых P меняет только outcome logit данной строки. При фиксированном proposal и $q_R$, из Cauchy–Schwarz
$$\max_{\|p\|\le1} q_R\sigma(l_0+p^Th)=q_R\sigma(l_0+\|h\|_2).$$
Достигается по направлению h (при h=0 постоянство). Если верхняя граница меньше u_min, никакой легальный P1 не откроет этот proposal на данном h. При h=(.6,.8), l0=-.6, q_R=.6 максимум .3592126<.5. Достижимость границы не означает, что admissible online history доведёт P до максимизатора. Если gate никогда не допускает этот proposal, online P1 не получает его labels. Начальный signal тогда требуется от лицензированных offline demonstrations или отдельно разрешённого контролируемого исследования, без обхода live authority. При одинаковых h,a,l0 и противоположных требованиях один общий порог их не различит. M и graph могут изменить future features, но только если доступен полезный причинный вход и память сохранена. Контрпример к обещанию полного отсутствия забывания: один и тот же h с y=0 и y=1; локальный descent одному увеличивает BCE другого. P3 ограничивает regret на реализованной последовательности, а не на альтернативной траектории действий.

**Лицензии и разделение данных.** У каждой записи sample/source SHA, права train/derive/distribute, язык, PII/consent, modality/source trust, group, timestamp, raw/label refs и transform digest. Речь/перефразы/голоса/сессии/устройства и шаблоны группируются до train/dev/calibration/locked и OOD; известный публичный split не sealed. Данные owner допускаются только с явным scope. FLEURS ru_ru остаётся кандидатом на ASR из ASTRA_03, полученного лицензированного product corpus нет. Для экрана нужны локальные инструментированные экраны/разметка, для TTS права диктора, для ambient wake negative/background/near-miss noise, для действий отдельный oracle. Доступность public текста не означает права на обучение/распространение. Train пишет только допустимые данные. Locked оценивается после freeze, экспериментальные N0/V traces не становятся свежим holdout. Old→New→Both на одной версии состояния/графа с отдельно frozen controls; replay admission сравнивает только конкретный конечный набор. Порог/качество вне finite test остаётся REQUIRES_DATA.

## 7. Фонарик — будущий независимый экзамен

Операция SET_TORCH (verb 12), typed (camera_id,enabled), absolute effect; status — чтение доверенного наблюдения/ответ, без самовольного переключения. API и доступность проверяет контроллер, подтверждение связывается с canonical args/expiry. Тест после отдельного разрешения на device. Train: перефразы ON/OFF/STATUS, отрицание, временные условия, corrections и ambiguous/unsupported метки. Отдельные говорящие, templates и контексты в locked. Одна F создаёт h_a и proposal. Hard-coded exact matching допустим baseline, в испытуемом learned semantics не подменяет решение.

Разделить 4 целевых исхода:
1. Семантика/неуверенность — независимый label; когда надо уточнить, молчать или отклонить.
2. Authority — точное согласие, актуальные OS permissions/resource, STOP, epochs, отсутствие чужого действия от DENIED.
3. Native постусловие — CameraManager/TorchCallback target id в ограниченном окне, отличать unavailable/ошибку/timeout. Регистрация может сообщить текущее состояние, а callback не несёт UNO ticket. Не выводить связь с конкретным вызовом из совпавшего id и времени. Только пригодный adapter независимо связывает наблюдение с предикатом, не с причинным эффектом.
4. Физическое состояние — отдельный измеритель светового потока/оператор независимой разметки с калибровкой до freeze, видит временное окно и baseline, не предсказание F. Независимый controlled counterfactual (paired no-dispatch, других writers нет/они известны) для attribution. Без валидного физического oracle сохранять hardware REQUIRES_DATA. Результат для OS-state и физики записывать отдельно.

Матрица случаев: on/off/status, уже нужное состояние (NOOP_ALREADY_TRUE после fresh prestate), неоднозначный camera id, permission unavailable, конкурирующее приложение, stale callback при регистрации, stop до и после D, revoke до C, crash PREPARED/после D, reboot generation, дубликат, отсутствующий physical sample. Неизвестное действие остаётся MAY_HAVE_EXECUTED/UNKNOWN. No blind retry, новая выдача по свежему intent и precondition. Обновление P1 только на заранее объявленный endpoint. Controlled learning для causal edge требует собственного сертификата; owner correction меняет смысл, не физический outcome.

Показатели: quality и coverage по классу, unauthorized effects, verified/ambiguous/unknown counters и отдельно attribution, старые/новые навыки до/после/restart на одинаковых matched tasks. Score после команды идёт в ledger только от oracle, prequential freeze до label. Абляции fixed F, P-only, M-only, P+M, A/B, empty/shuffle G, persistence, Markov, table, grammar/rule search и сильный synthesis с раскрытыми priors. Одинаковые доступные observations/labels, splits, бюджет, task attempts и resource accounting. Не сравнивать обучившийся arm с baseline, лишённым того же input/labels. Раздельно per-issued и per-verified completion. При 0 из N iid ошибок exact upper $1-\alpha^{1/N}$, иначе измерить и отразить кластерную зависимость. O06 пороги до теста.

## 8. Ресурсы, границы и NCR-EVO

$P_{alloc}=Vd+951d+2d^2+4md+J[2\chi d^2+\chi bd+(\chi+1)d]+902(d+1)+V+(d/b)(2d+5)+33$ у dense B2. Вычесть $318(d+1)$ для free. По O08 фиксировать $E_{total}/N$ (все issued) и $E_{total}/S$ (verified completions, $S>0$), с учётом энергии отказов. $S=0$ не даёт конечного результата по второй метрике. Сравнение среди profiles, прошедших независимые hard quality/coverage/risk/memory/latency gates. Иначе ресурсный рекорд бессмысленен. Конкретные пороги оставлены владельцу. Документы G4 не измеряют безопасность A52.

NCR-EVO (ASTRA_06 + R4.1 §§13,25) — отдельная изолированная лаборатория, без runtime Android capability. Имеет typed DSL, interpreter cap, immutable validator/oracle/safety, отдельные Θ, mutator θ и surrogate φ. Пусть n raw≤256 на поколение, H фильтрует parse/type/static resource, canonical dedup оставляет N. Заморозить φ, budget и admission, затем b≤16 draws с replacement по $\pi_i=\epsilon/N+(1-\epsilon)\mathrm{softmax}(A_i/T)$. Для $N=0$ или $b=0$ нет IPW оценки. $p_i=1-(1-\pi_i)^b$. При fixed pool и fully observed loss в каждой evaluated программе $E[I_i\ell_i/p_i]=\ell_i$. Censoring и выбор после outcome требуют другой процедуры.
