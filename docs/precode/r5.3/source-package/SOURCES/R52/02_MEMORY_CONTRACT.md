# R5.2 / IR02 — точная память и разрешение конфликтов (КАНДИДАТ)

**Источники:** ASTRA_01 S4, ASTRA_04, R5.1 `03_MEMORY_EXACT_CONTRACT_DRAFT.md`.

## Что доказано

Нейронный результат `r=Σ_i ω_i v_i` **не является без потерь**. Пара `v,-v` при равных весах даёт ноль: из агрегата нельзя восстановить обе исходные записи, их происхождение и противоречие. Смысловой результат нельзя использовать как доказательство точного воспоминания.

## Два режима, один организм

- `RetrieveSemantic(q)` — числовое представление для общего F, исключительно `SUMMARY_ONLY`, без обещания полного перечня фактов.
- `RetrieveExact(query, scope, k, budget)` — конечное детерминированное чтение исходных записей. Не второй мозг, не второй reasoning-агент; обычная локальная операция хранилища, после которой найденные данные поступают в UNO.

Запись обязана содержать идентификатор хранилища, номер поколения slot, digest payload, type/kind (`USER_DECLARED`, `OBSERVED`, `VERIFIED_COMPLETION`, `HYPOTHESIS`), version, source/provenance, consent scope, время и boot identifier, TTL/expiry, model-digest совместимости. Сырые данные хранятся или ссылаются на валидируемый bounded raw payload. Исторический результат не превращается в `VERIFIED_CURRENT` без нового trusted readback.

## Результаты запроса и приоритеты

- `DENIED` — запрошенный scope не разрешён; ни один защищённый payload не выдаётся.
- `UNKNOWN` — полноту/целостность/источник/версию подтвердить невозможно; payload может быть исключён.
- `TRUNCATED` — результаты обрезаны limit k, временем или бюджетом; выдаются `continuation` и `matched_lower_bound`, при конфликте `conflict_seen=true`, **но не ложная полнота**.
- `CONFLICT` — **только после полного сертифицированного scan указанного snapshot** и перечисления всех релевантных конфликтующих записей в пределах k. Если полный scan/список невозможен → TRUNCATED/UNKNOWN.
- `COMPLETE` — все разрешённые и индексированные записи, удовлетворяющие запросу на неизменном snapshot, перечислены и validated. Не означает истинность мира и не означает, что сохранена вся история до TTL/eviction.

Нельзя возвращать `COMPLETE` при `k < matched_count`, при revocation до выдачи или если snapshot изменился. `CONFLICT` не означает, что одна из записей истинна; при неоднозначной канонизации предмета/времени — `UNKNOWN`.

## Гарантия и ограничения

`COMPLETE` обоснован только при целостном конечном индексе и raw payload, корректных правах, версии, snapshot isolation, проверенной provenance и исчерпывающем просмотре scope. Проверка consent нужна в начале, перед выдачей и перед использованием в решении. Изменение `store_generation`, `slot_generation`, consent-epoch, boot/session version либо source revoke инвалидирует предыдущие refs и результат, предотвращая ABA/stale use.

Модель не может изменять provenance, permissions или теги trusted verification. Ложный timestamp из недоверенного источника остаётся недоверенным. Никаких скрытых расширений памяти за пределы заявленной ёмкости (в ASTRA ≤4096 индексированных слотов и ≤4096 payload slots по ≤4KiB) без новой ресурсной оценки.

## Оракулы будущей реализации

1. `v,-v` не уничтожает две исходные записи при exact retrieval; `SUMMARY_ONLY` не выдаёт `COMPLETE`.
2. 17 подходящих записей при `k=16` → `TRUNCATED`, даже если среди 16 найден конфликт.
3. Same slot/new generation (ABA) → старый ref недействителен.
4. Revoke в процессе чтения → `DENIED` или без раскрытия данных, но не COMPLETE.
5. Повреждённый payload, time/boot conflict, несовместимый digest → `UNKNOWN`.
6. Изменение данных между scan и commit → snapshot invalid, retry only with fresh permission.
7. Известные взаимно исключающие claims с равным временем → `CONFLICT` после полного scan.
