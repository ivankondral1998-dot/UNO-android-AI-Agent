# UNO-N0-04 / Android physical sensor test / frozen protocol / 2026-11-05

Status **SPECIFIED_UNTESTED**; source implementation not validated on phone. Owner authorized Android experiments and GitHub Actions on 2026-11-05, research branch only. R5.3 G4 and G5 still not approved. No production code, no GitHub `main` changes, no release publication.

## Hypothesis to falsify

Can an offline, event-neuron graph with **no learned numerical synaptic coefficients** predict the next *physical* accelerometer-derived categorical movement event better than (a) last-state persistence and (b) a first-order numeric Markov lookup baseline, while retaining an A-context skill across sequential A→B→A and across Android process restart?

No promise of better prediction. A failure is a valid experimental result.

## Sensors / independent observations / privacy

- Data source: Android `SensorManager` TYPE_LINEAR_ACCELERATION, fallback TYPE_ACCELEROMETER with exponential gravity estimate (filter numeric constants 0.92/0.08). Normalized magnitude per 250 ms physical sensor window; labels STILL (<0.65 m/s²), MOVE (0.65 to <2.5), JOLT (≥2.5). These thresholds are engineer-chosen; phone accuracy and drift must be measured. Phone does not report actual causal actions, just sensor data. Therefore `SensorEvent` is independent of the network's predictions but is **not** an independent Android operation readback or a proof of user intent.
- Prediction uses previous two observed categorical windows to guess the **next** physical window. The next sample is not available at prediction time. The sensor feed is not generated by the app. No fabricated synthetic world oracle.
- Qualitative inputs: mode supplied by human A/B, previous event, older event and derived RISE/FALL/FLAT. Human-supplied A/B **is a contextual hint**, not something network discovers. There is no hidden extra sensor input.
- Offline, foreground only, no runtime permissions, no INTERNET, no network services, no mic, no background data capture, no real actions. Processed labels and structural graph persisted in app-private `SharedPreferences` with SHA256 envelope. Raw accelerometer streams not saved; reports may be copied manually.

## Algorithm fixed before experiment

One shared `NeuralGraph` containing qualitative conjunction neurons. A node fires when *all* its typed REQUIRED cues match; it EMITS one of STILL/MOVE/JOLT. Maximum-specificity matching selects output; conflicting maximum specificity or contested rule falls back to previous-state prediction. If no rule fires, also predict the previous event.

After a training-window prediction has been scored against the **later physical** sensor observation: on mismatch build a conjunction for MODE+PREV; if already present, refine to MODE+PREV+OLDER+TREND. Identical complete conjunction with different verified outcome is marked contested instead of overwritten. Fixed maximum 120 nodes, no learned float/int synaptic coefficient. Counts/indices/thresholds still numeric. This is a *preprogrammed* structural update rule, not autonomous invention of new sensor types or general reasoning. Rule matching is scanned and cannot claim bounded large-model energy. No formal proof of stability for all contexts.

Comparison uses exactly the same training windows: (1) persistence = previous label, (2) Markov baseline count table `(mode, previous)->next`, (3) always-STILL. Markov counts **are numeric**; this is a separate baseline and not part of weightless graph. No online graph/table learning in frozen tests.

## Frozen device protocol / hard gates

Device: Samsung Galaxy A52 / Android 14 first. Five stages, each **80 valid predictions**, 250 ms windows, timeout 60 seconds; app pauses and aborts partial stage (rollbacks model and table) if backgrounded. At least **8 changes of sensor class** per stage required or the stage is `INVALID_LOW_MOTION_DIVERSITY` and cannot support an adaptation claim. User should move safely and gently; no drops/violent shaking.

1. TRAIN A: mostly still with occasional gentle tilts or short movements; 80 prospective predictions scored before updates.
2. TEST A: repeat A pattern, no learning; record model/persistence/Markov/always-STILL accuracy and timings.
3. TRAIN B: change movement distribution with regular gentle repeated motions; 80 prospective predictions, learn.
4. TEST B: repeat B, frozen; record same metrics.
5. **Close and reopen the app** (state must reload with SHA256 verified), then TEST A RETENTION: recreate A, frozen, 80 predictions. App requires new Activity after saved step 4.

**Accept claim of better predictive adaptation only if** all five stages have ≥8 class changes, new structural neurons appeared during training, TEST A and TEST B and RETEST A each have graph correct ≥ max(persistence correct, Markov correct), and disk restore reports `PASS_SHA256`. If any criterion fails report FAIL or INCONCLUSIVE without changing the card. This comparator is challenging; do not optimize the protocol after seeing output. A retest score merely comparable to baseline is not proof of retention; also compare A retest to A test, and document variation in voluntary movement.

`0 ms` rounded isn't zero time. Instrumentation: sensor event count, skipped stale windows, 250ms inference time mean/p95/max in microseconds, two heap snapshots, train/eval scores, neuron/synapse count and CONTESTED outcomes, save/restore SHA256. Does not measure PSS, native heap, energy, battery, heat, model intelligence or ability to discover an unknown physical cause.

## Invalidation/negative conditions

No sensor, too few sensor events, fewer than 8 class changes, app pause/interruption, corrupted checkpoint, no rule growth, baseline superiority, catastrophic old-context retention: record the failure as-is, do not silently claim a pass. After in-app reset, the old experiment state is deliberately replaced at owner's explicit request; do not reset without explicit button press.

Research build: distinct package `org.unovyra.n004research`, so it installs separately from N0-03 and does not replace its data. Isolated GitHub workflow on research branch; no Jarvis/PMB/production modifications. APK signature generated for each research build and not an official release identity.
