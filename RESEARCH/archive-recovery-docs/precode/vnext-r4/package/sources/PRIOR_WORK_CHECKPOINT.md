V01_V20_INTEGRITY.json содержит сверку вложенных блоков исходников с индексом. Хронология в TXT — историческая отчётность, не новый запуск на A52. V08 завершён safety abort по его записи.

- R3 и R4.1 повторно прогнаны в пределах бумажных фикстур. Точный вывод приложен.

## Адресные исправления к R3 и унаследованной R4.1

1. **Допуск.** Строку «обучение не разрешено» в ERRATA_R3 применять только к производственному обучению. AGENTS.md и docs/CURRENT_TASK.md исследовательской ветки фиксируют отдельное разрешение от 05.11 для версионированных изолированных кандидатов на ПК. Максимум 600 секунд и 2 GiB RAM на прогон, максимум 3 прогона одного кандидата до ревизии. Задача, данные, seed, метрики и пороги фиксируются до прогона. Текущая сдача — аудит и архивирование. Производственный код/обучение, Android APK и действия на устройстве, Actions, публикации и утверждение baseline остаются вне этого допуска.
2. **UNKNOWN.** В разделе обновления графа запись a=0 не позволяет вычислять выражение с неопределённым y. Сначала проверить наличие допустимого бинарного y, provenance и все условия commit. При отсутствии любого условия вернуть исходный W_G и граф без вычисления градиента. При успешной проверке выполнить E02. Учительская коррекция относится к семантическому label. Сенсорный отсчёт — отдельное наблюдение. Подтверждённый независимый Android endpoint — отдельный источник физической метки.
3. **Формула L5.** Исправление R3 устраняет ошибку краткой формулы vNEXT. В унаследованной R4.1 §10.2 baseline уже записан корректно по решениям. Запрещено переносить ошибку краткого пересказа на оригинальную формулу. Численные фикстуры проверяют контрпример, а не обучение.
4. **Энергия.** R4.1 §9.2 упоминает джоули «на выданную задачу», а vNEXT и README — на подтверждённое завершение. Для будущего сравнения фиксировать обе величины E_total/N и E_total/S на одной батарее, где N — все выданные задачи, S — независимо подтверждённые успехи, E_total включает отказы и прочие попытки. E_total/S при S=0 не имеет конечной оценки, профиль не участвует в выборе. Сравнивать основной E_total/S только при выполнении заранее заданных ограничений качества, покрытия, риска и ресурсов. Предложенный порядок выбора остаётся O08.
5. **Проверка доставки.** R3 использует assert, поэтому запуск Python с -O удаляет проверки. Исторический скрипт запускать обычным python. Независимо от него внешний ZIP сверяется явным сравнением CRC, перечня, размера и SHA-256 всех вложенных файлов.

## Открыто для следующей сессии

Построчный повторный аудит каждого ASTRA_01–12 и исторических дублей, содержательное исполнение всех V01–V20, неподписанный сырой N0-07 trace, полноценный обученный Θ, лицензированный locked evaluation и независимые измерения PSS/нагрева/энергии на A52 остаются отдельными задачами. G4 и допуск G5 остаются раздельными. Само архивирование не утверждает архитектуру. Архив сохраняет документы проекта и подтверждённую контрольную точку, а не внешние данные, которых не было в рабочей копии.
