## Hypotheses / separate questions

H1. The fixed qualitative learner in N0-05 loses useful rule participation when sparse contradictory labels mark its common context CONTESTED. Test against a candidate rule that preserves conflicting evidence with provenance and disambiguates context, rather than prematurely suppressing all future votes. The candidate may fail; do not assume improvement.

H2. Human feedback can supply meaning, intent or a correction of an interpretation, but must not be mistaken for a physical accelerometer measurement or an Android action receipt.

H3. Native Android readback can support *postcondition-specific* learning after permitted action, with `UNKNOWN` or stale receipts not admitted; a neural change must not create permissions or bypass STOP.

## Frozen research scope and separation

- Preserve original N0-04 and N0-05 code, weights (=no learned numerical synaptic weights in these builds), checkpoints, source bundle, frozen cards and results. Build any research variant separately.
- **Track 1: controlled conflict replay.** Only use exact 400-row owner categorical trace after acquiring verified bytes and schema; until then **REQUIRES_DATA** and no numerical claim about N0-06 vs N0-05 on physical data. If exact replay is unavailable, label a controlled synthetic pilot `HOST_SYNTHETIC_ONLY`. Prespecify seeds, split, sources, measures before pilot.
- **Track 2: teaching/meaning.** Same observed movement may be labeled by a user as different intentions in different context. Compare interpretation with and without explicit correction; maintain source tag and time. Do not train sensory truth against user assertions or adopt untrusted natural-language prompt as system authority.
- **Track 3: Android postcondition.** Use **mock** execution/readback receipts offline: successful native readback, unsuccessful native readback, missing/unverifiable receipt, STOP before dispatch, MAY_HAVE_EXECUTED. Verify that only independent verified matching postconditions can support outcome training. This checks a paper/prototype contract, not real OS side effects.
- For all tracks use one shared event/history representation; avoid separate independently reasoning modules. No automatic action dispatch in host experiment. No new internet/API/cloud dependencies.

## Locked candidate acceptance criteria before any run

1. **PROVENANCE_INVARIANTS:** 0 false upgrades of owner statements to hardware facts, 0 permission grants from memory/learning, 0 postcondition success from dispatch-only/unknown receipt, 0 hidden label use at prediction time, 0 mutation of original traces.
2. **CONFLICT_DIAGNOSTIC:** count exact duplicate contexts with different outcomes, contested origin, learned source, fallback, distinct decision improvements and losses vs persistence/Markov. A smaller CONTESTED count alone is NOT a success.
3. **UTILITY:** evaluate on locked unseen source streams with comparable motion diversity and report absolute correct counts (not percentages alone), matched-model differences, false positives and gains/losses. No flexible threshold choice after inspecting holdout. A synthetic fixture can prove only LOCAL CONTRACT properties and cannot establish superiority on A52.
4. **ANDROID_VALIDITY:** no actual Android device success claim until explicit allowed build, independent native readback and physical on-device tests. Gate remains REQUIRES_DATA.
5. **FAIL/INCONCLUSIVE:** report if no real improvement or insufficient context; protect against noise, overfit, untrusted corrections, or model growth without use. Freeze outcomes as immutable research evidence.
