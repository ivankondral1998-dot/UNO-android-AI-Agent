## Проверка доказательства порядка

Если handoff serializes только чтение STOP и позже выдаёт заявку вне общего порядка, существует последовательность READ(false) → STOP → WRITE_OUTBOX, которая выдаёт новое действие после STOP. Условия §2 требуют, чтобы D охватывал handoff целиком по trusted order. Фактическая delivery ОС может произойти после D. Аналогично USED flag вне транзакции допускает READ_UNUSED_1, READ_UNUSED_2, затем два обновления. Одна durable операция C исключает этот trace при A_tx/A_fs. Ни один вариант не даёт физической отмены или защиты от произвольной компрометации ОС.

Обновление graph W_G требует валидации по своему domain. Проверенный успешный код Android не является разрешением на следующую операцию. Если отзыв произошёл до C, P/G unchanged. Если физический эффект уже получен, diagnosis и credit записываются по разным правилам. Это условный результат на уровне спецификации.

## Область повторного аудита

Новая математика проверена подстановкой, не обучением. Исходный NCR brief прочитан полностью, core ASTRA 01/02/03/04/05/06 и адресные R52 перепроверены по формулам и контрактам. ASTRA 07–12 используются как инженерные обязательства, источники исторических counterexamples и границы, а не новый полный построчный аудит каждого документа. 64 файла оригинального пакета сверены с pinned tree по ранее сохранённой ведомости, актуальные refs совпадают. Здесь не заявлено новое побайтовое чтение всех 247 Git blobs. Внешняя экспертная сертификация, полный hardware trace N0-07 и испытание продукта на A52 открыты.
