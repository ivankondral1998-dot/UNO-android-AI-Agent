# Jarvis V21 — архитектура единого локального агента

**Цель / TARGET (01.11.2026), не заявление о реализованной Android-сборке.**

```text
Локальное восприятие (ASR / датчики / состояние телефона)
                        ↓
         ЕДИНАЯ НЕЙРОННАЯ ОРГАНИЗАЦИЯ JNO
   обученные начальные веса + оперативное состояние
   пластичные связи + обучение + проверяемый рост
                        ↓
     Намерение / гипотеза действия (не разрешение)
                        ↓
      Минимальное локальное исполнение Android
        permissions / STOP / confirmations
                        ↓
      Native readback / evidence / последствия
                        ↓
    Обновление опыта и состояния этой же JNO
```

Это схема **функций**, не новые агентные сервисы или мосты. Не создавать отдельный BrainPort, множество LLM, оркестраторы и сервис памяти как замену нейронному ядру. При этом ОС требует системных вызовов для оборудования; запрещено путать Android API с удалённым API.

## Старый Android-код как источник, а не новая архитектура

- `HearingEngine.kt` — цикл микрофона, ограниченные очереди и отмена. Офлайн-декодер/ASR и TTS следует проверить отдельно.
- `LocalBrainModel.kt` — примеры ограниченной математики INT8, но старый классификатор/веса/жёсткий `veto()` не переносить.
- `ActionEngine.kt`, `AndroidOperationAuthority.kt`, `CompletionVerifier.kt` — возможности Android, ограничения полномочий, readback. Переносить **минимально необходимое**.
- Исследовательский `cognitive/` — возможный источник тестов и идей; не переносить старую цепь посредников автоматически.
- `CELL` — вне штатной архитектуры новой V21.

## Реальный статус

Восстановленная V21 от 31.10.2026 включает legacy cloud code и `INTERNET` в AndroidManifest. JNO G2 отдельно обучена на узком симуляторе (2 контекста, 6 действий); 01.11.2026 подготовлен отдельный Kotlin/JNO overlay с host-тестами. Он не является доказательством готового Android цикла. Оффлайн, понимание языка, перенос сложных навыков, саморасширение и регенерация — открытые инженерные/исследовательские задачи.

## Опорные принципы

CPU/PSS/battery budget; проверки повреждённых весов и снимков; контроль старых навыков; fail-closed authority; явная пропускная способность и тайм-ауты; состояние сохранять атомарно; все шаги в одном жизненном цикле задачи с отменой. Удалять старую инфраструктуру **только в новой реализации после проверки функций**, а исторические источники оставить доступными.
