## Мотивация и доказанный исторический дефект

Исходный Grok/Work B2 scaffold из сохранённого `UNO_WORK_COMPLETE_PAPER_HANDOFF_2026-11-03(1).zip`, каталог `06_NON_NORMATIVE_OLD_SCAFFOLD/reference`, содержит `uno_ref/config.py:ResourceBudget.charge()`, проверяющий **только MAC**. `uno_ref/engine.py:NeuralEngine.tick()` резервирует перед `_z()` энкодер/селектор MAC, а потом на каждом шаге F снова только MAC.

Независимый воспроизводимый эксперимент на исходном Python reference:

- `ModelConfig(d=64,vocab=256)`, детерминированные fixture weights, `TEXT token=0`, `forced_prefix=1, forced_k=1`.
- `ResourceBudget(remaining_mac=1000000, remaining_bytes=0, remaining_tokens=0, remaining_ns=0)`.
- **Наблюдение:** `status=COMPUTED_UNTRAINED`, `mac=125124`, `remaining_mac=874876`, остальные три бюджета **0** без abort. Это **FAIL** модели «все четыре ресурса контролируются»; прежние Python PASS этого не покрывали.
- В предыдущем независимом историческом baseline `pytest` повторно завершился **61 passed** — это подтверждает, что исторический тестовый набор **не ловит именно этот дефект**, а не доказывает отсутствие дефекта.

Исходный архив и его Python-эталон **не менялись**.

## Внедрение

- `android/core/src/main/kotlin/org/unovyra/uno/core/ComputeBudgetGate.kt`.
- `android/core/src/test/kotlin/org/unovyra/uno/core/ComputeBudgetGateTest.kt`.
- Запуск из существующего `AllHostTests.kt`: новые 17 negative/host-тестов добавлены к общей строке результата. `scripts/host_verify.sh` и `:core:unoHostTests` будут использовать этот runner, **но в этой сессии их полный прогон на новой ветке не выполнен**.

**Контракт допусков:** бюджет MAC и токенов монотонно расходуется при `admit`; `scratchBytes` — резерв **пиковых одновременных временных** байт и возвращается `release()` через `finally`; дедлайн проверяется через передаваемое `elapsedRealtimeNanos`; одновременно активных допусков не больше явно заданного `maxInFlight`.

Защищены граничные случаи: нулевой бюджет нужного ресурса, отрицательные значения, переполнение `Long`, частично валидные запросы, чужой/устаревший permit, дважды выполненный `release`, необратимый STOP, ошибка внутри callback и гонка списания MAC между восемью потоками. При **любом** отказе `tryRun` не вызывает дорогое тело. Нулевой estimate по всем координатам отвергается.

**Не выдавать это за физический планировщик:** реальный расход CPU/RAM/батареи или времени **не измеряется** этой моделью. Время внутри callback не ограничено автоматически: исполнитель должен проверять `isCurrent` между дорогими шагами и самостоятельно ограничивать отдельный native kernel. STOP не отменяет уже вошедшую в native/CPU операцию. Модель/оператор F пока не подключены, поэтому новый primitive **не исправляет** старый Python `NeuralEngine.tick()` и не доказывает ресурсную безопасность будущего UNO.
