# UNO — решение владельца: один постоянный Android APK (2026-11-11)

**Область:** доставка испытательного UNO на собственное устройство владельца. Это более новое явное решение владельца, чем ограничение R4, требовавшее обязательно найти старый ключ. Исследовательские оригиналы и старые APK не изменяются.

## Решение

1. **Один постоянный пакет:** `org.unovyra.uno`; одно установленное приложение UNO с одним launcher. Для новых устанавливаемых владельцем сборок запрещены суффиксы `.ci<run>`, `.test`, новые applicationId и случайные сертификаты.
2. **Допустима новая подпись при первом переходе.** Старый неизвестный debug signing key искать не обязательно. При первом создании постоянного канала generate RSA-3072 PKCS12 keypair локально на компьютере владельца, вне GitHub; одна и та же пара используется в каждой последующей сборке.
3. **Обновления:** тот же applicationId, тот же signer SHA-256, строго больший versionCode; иначе build FAIL до передачи владельцу. Без автоматической установки, удаления, переустановки, публикации или стирания данных.
4. **Безопасное хранение:** private keystore + сгенерированный пароль + публичный fingerprint и все собранные APK хранятся в одной отдельно защищённой владельцем папке вне репозитория. Требуется резервная копия на принадлежащем владельцу зашифрованном носителе. Скрипт не передаёт ключ в GitHub/Actions/чат. На Windows/общем ПК права доступа и шифрование самой папки **не обеспечиваются** этим Python-скриптом.
5. **Первый переход ограничен Android:** новый сертификат и/или новый packageId **НЕ обновят старый установленный APK** и **НЕ перенесут автоматически его app-private данные/AndroidKeyStore**. Старое приложение остаётся нетронутым, пока владелец не разрешит перенос/удаление после проверки сохранности данных. Возможен временный второй значок при первом переходе; после него новые версии одного UNO обновляют предыдущие без новых значков. Нельзя обещать бесшовную миграцию без проверенного экспорта.
6. **Продукт:** существующий единый launcher, одно действие диагностики; не добавлять тестовые APK или россыпь диагностических кнопок ради этой задачи. Наличие механизма обновления не равно готовности нейро-ядра.

## Реализация-кандидат

- `android/scripts/owner_permanent_channel.py`: `init` создаёт новую локальную подпись **один раз** и отказывается повторно перезаписывать папку. `build` формирует новую подписанную APK с последовательно возрастающим versionCode, сверяет signer и прежний APK, сохраняет неперезаписываемый архив + manifest, не устанавливает ничего.
- `android/app/build.gradle.kts`: явно разрешает новый канонический packageId и versionCode 1 для первой сборки, но запрещает параллельный CI suffix и GitHub Actions signing.
- `android/scripts/test_owner_permanent_channel.py`: реальные проверки keytool и mock-сценарии двух последовательных версий. Не равны реальной Android сборке/проверке на A52.

**Команды на собственном защищённом ПК** (папка должна ещё не существовать; Windows-пример):

```powershell
python android/scripts/owner_permanent_channel.py init --owner-dir "D:\UNO-owner-private"
python android/scripts/owner_permanent_channel.py build --owner-dir "D:\UNO-owner-private"
# После первой проверенной установки новый build создаст v2 с тем же ключом.
python android/scripts/owner_permanent_channel.py build --owner-dir "D:\UNO-owner-private"
```

Для `build` необходимы локальные Android SDK35, NDK, Gradle, `aapt`, `apksigner`, JDK и все зависимости проекта. Не запускать из GitHub Actions: владелец не давал нового разрешения на Actions в данном поручении.

## Приёмка и статус

**HOST_TESTED (изолированные проверки генерации ключа и mock-версий)** — 5/5 локальных тестов, включая реальный `keytool` RSA-3072. **ANDROID_BUILT для нового канала: FALSE** (нет SDK/Gradle в данной среде). **DEVICE_VERIFIED: FALSE**. **OWNER_KEY_GENERATED_FOR_REAL_USE: FALSE** — тестовые ключи в временных каталогах удалены тестовым окружением, постоянный ключ должен быть создан на принадлежащем владельцу защищённом ПК. **MIGRATION_VERIFIED: FALSE**. `main` не менялся, история не переписывалась.
